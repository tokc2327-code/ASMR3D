# 11 模块：桌面主进程

[[00-索引]] · 相关：[[02-架构与数据流]] · [[12-模块-原生捕获脚本]] · [[24-功能-直播截获与录制]]

## 职责

`desktop/` 只在 Electron EXE 或桌面开发模式中运行。它负责渲染进程不能直接接触的本地能力：窗口、文件系统、下载落盘、输出目录、直播进程、WAV 分段录制。

## `main.cjs`

### 窗口与安全

- 创建主窗口并加载 `renderer/index.html`。
- 桌面版启用 `contextIsolation`，通过 `preload.cjs` 暴露受限 IPC。
- 保持单窗口音频工具形态，不做多标签页。

### 统一输出目录

解析顺序：

```text
用户临时更改的保存位置
  → EXE 同级目录下的“输出”
  → 音乐\asmr3d输出
  → 系统临时目录
```

开发模式（直接运行 `desktop/main.cjs`）使用项目中的 `dist\输出`。

目录处理要点：

- 目录不存在才创建；
- 已存在也做可写性探测；
- 同名文件自动加 `-1`、`-2` 后缀；
- 避免对盘符根目录直接调用 `mkdirSync`。

### IPC 中枢

主要 IPC 类别：

| 类别 | 示例能力 |
|---|---|
| 输出目录 | 取得路径、更改路径、打开目录 |
| 保存文件 | 把渲染或转换后的 Blob 写入磁盘 |
| 直播扫描 | 枚举活跃音频会话 |
| 直播控制 | 开始截获、停止截获 |
| 录制控制 | 开始录制、查询状态、结束并合并 |

具体通道通过 `preload.cjs` 白名单暴露，渲染进程不能任意调用 Electron API。

### 会话音量恢复

直播“压低原声”会改目标应用的会话音量。主进程负责三层恢复：

1. 正常停止截获时恢复；
2. 窗口关闭 / 应用退出时恢复；
3. 如果程序被强制结束，把原音量写入状态文件，下次启动自动恢复。

状态文件：

```text
%APPDATA%\asmr3d空间渲染器\source-volume-state.json
```

## `preload.cjs`

用 `contextBridge.exposeInMainWorld()` 暴露一个命名空间，把每个方法转发到固定 IPC 通道。它同时限制参数类型，避免渲染进程拿到任意 Node 能力。

模型修改时注意：

- 新增 IPC 必须同时改 `main.cjs`、`preload.cjs` 和 `app.js`；
- 不要为了方便直接开启 `nodeIntegration`；
- 文件路径由主进程决定，渲染进程只提供文件名和内容。

## `live-capture.cjs`

### PowerShell 解析优先级

```text
ASMR3D_POWERSHELL 环境变量
  → 包内 resources\pwsh\pwsh.exe
  → PATH 上的 pwsh
  → Program Files / LOCALAPPDATA 常见安装位置
  → Windows PowerShell 5.1（会提示不支持进程回环）
```

包内路径必须排在 PATH 之前，否则用户系统里的旧版本可能被误用。

### 捕获启动

主进程启动：

```powershell
pwsh -File resources/probe_process_audio.ps1 `
  -StreamToStdout `
  -ProcessId <pid> `
  -DurationSeconds <seconds> `
  -SilenceTimeoutSeconds <seconds> `
  -StopOnProcessExit true
```

### stdout 协议

```text
第一行：UTF-8 JSON 头
后续：连续交错 float32 little-endian PCM
```

JSON 头包含进程名、PID、采样率、声道数、样本格式和会话信息。主进程解析头后把 PCM 切成约几十毫秒的块，通过 IPC 发给渲染进程。

### 状态与错误

- 进程退出时，主进程收到 `exit` 并通知渲染进程；
- 目标进程退出或持续静音可由脚本自身结束；
- 捕获失败时保留脚本 stderr，便于定位 CLR、COM、权限或设备问题；
- 调试可设置 `ASMR3D_CAPTURE_LOG=<path>` 记录实际命令行。

## `segment-recorder.cjs`

### 写入

- 接收 limiter 之后、monitorGain 之前的立体声 PCM；
- 按 5 / 10 / 30 分钟切换临时分段；
- 每段先写占位 WAV 头，完成后回填长度；
- 段间按采样点边界切，无重叠、无空洞；
- 24-bit 写入约 288 KB/s。

### 格式校验

合并前检查所有分段：

- 声道数一致；
- 采样率一致；
- 位深一致；
- 分段长度与采样点累计一致。

### 合并

```text
读取 segments.json
  → 创建最终 WAV
  → 复制 WAV 头
  → 顺序复制每个分段的 PCM 负载
  → 校验总长度
  → 写 SHA-256
  → 删除临时分段
```

合并采用流式复制，内存占用与录音时长无关。总量超过约 4 GB 时改用 RF64。

### 失败处理

- 只有最终文件完整写出并通过长度校验后才删除分段；
- 合并失败时保留全部分段和元数据，允许重试；
- 峰值磁盘占用约为成品的 2 倍。
