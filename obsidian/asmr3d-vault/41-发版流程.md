# 41 发版流程

[[00-索引]] · 相关：[[13-模块-构建与工具脚本]] · [[40-运行与打包]]

## 发版总流程

```text
确认代码和文档
  → 预览版本替换
  → 执行版本号更新
  → 构建 EXE
  → 启动验证
  → 生成 GitHub 包
  → 上传源码与 Release
  → 同步 Wiki
  → 复查页面与资源
```

## 1. 版本号

当前版本：

```text
package.json      0.3.1
对外版本           v0.3.1 公测版
Release 标签       v0.3.1-beta
```

版本字符串分布在约 20 个文件、70 多处。不要手动逐个替换。

先预览：

```powershell
node tools\bump_version.mjs 0.3.1 --dry-run
```

确认文件数正常，一般为 20 个。再执行：

```powershell
node tools\bump_version.mjs 0.3.1
```

该脚本会更新：

- `package.json`；
- 界面版本徽标；
- 窗口标题；
- 构建目录和文件名；
- Release 标签；
- README / docs / wiki 中的字符串；
- 上传脚本默认标签。

## 2. 发布前检查

### 代码

```powershell
node --check renderer\app.js
node --check desktop\main.cjs
node --check desktop\live-capture.cjs
node --check desktop\segment-recorder.cjs
```

### 关键功能

- 启动应用；
- 播放内置素材；
- 切换四种渲染方式；
- 拖动进度条；
- 停止后位置保留；
- 导出 16-bit 和 24-bit WAV；
- 导入 / 导出参数模板；
- 执行视频转音频；
- 扫描直播会话；
- 截获并实时调方位角；
- 开始同步录制、停止、合并；
- 用 `inspect_wav.mjs` 检查录制文件；
- 确认会话音量正常恢复；
- 确认输出目录为 `<EXE目录>\输出`。

### 文档

- README 版本和功能；
- Wiki 安装、界面、FAQ、更新日志；
- `docs/项目上下文交接.md`；
- Obsidian 索引和笔记；
- Release 说明与资源名一致。

## 3. 构建

```powershell
node tools\build_exe.mjs
```

或：

```powershell
npm run exe:release
```

产物：

```text
dist\asmr3d-v0.3.1-win-x64\
dist\asmr3d-v0.3.1-win-x64.zip
dist\asmr3d-v0.3.1-mobile\
dist\asmr3d-v0.3.1-mobile.zip
```

确认：

- 包内 `resources\pwsh\pwsh.exe` 存在；
- 包内 `resources\probe_process_audio.ps1` 存在；
- `app.asar` 含最新界面；
- 图标是当前版本；
- 解压后 EXE 能启动。

## 4. 生成 GitHub 包

```powershell
node tools\build_github_package.mjs
```

输出：

```text
dist\github-package\source\
dist\github-package\release-assets\
```

### 源码包内容

当前包含：

```text
renderer
desktop
docs
wiki
tools
materials
android
```

如果希望把 Obsidian 知识库也放进源码仓库，需要把 `obsidian` 加入 `build_github_package.mjs` 的目录数组，并同步 ignore 规则。

### Release 资源

发布目录中应只放要公开的文件，例如：

```text
asmr3d-v0.2-win-x64.zip
asmr3d-v0.2-mobile.zip
```

确认：

- `tools\.github-token*` 不在源码包；
- `.git`、`node_modules`、`dist` 不在源码包；
- Android 工具链缓存不在源码包；
- 没有用户音频和临时分段；
- 没有本地日志。

## 5. GitHub 令牌

上传脚本读取优先级：

```text
GITHUB_TOKEN 环境变量
  → tools\.github-token
  → tools\.github-token.txt
```

当前本机使用：

```text
tools\.github-token.txt
```

细粒度令牌需要：

```text
Contents: Read and write
```

令牌过期后重新生成，并更新本地文件。不要提交令牌。

## 6. 上传

```powershell
node tools\github_upload.mjs
```

脚本行为：

1. 把源码树推送到 `main`；
2. 更新仓库 description；
3. 更新 topics；
4. 创建或复用 tag；
5. 创建 / 复用 Release；
6. 上传 `release-assets/`。

可选环境变量：

```powershell
$env:ASMR3D_COMMIT_MSG="release: v0.3.1"
$env:ASMR3D_REPLACE_ASSETS="1"
$env:ASMR3D_SKIP_SOURCE_UPLOAD="1"   # 已用 git push 时，跳过 API 源码覆盖
node tools\github_upload.mjs
```

### 重要风险

源码推送是 **force 覆盖**。如果有人在 GitHub 网页上直接修改了 `main`，本地推送会覆盖那些修改。

发布流程应以本地源码树为唯一真实来源。

## 7. 同步 Wiki

```powershell
node tools\push_wiki.mjs
```

确认 Wiki 页面：

- 首页；
- 安装与运行；
- 界面导览；
- 渲染方式与空间参数；
- 参数模板；
- 导出与输出目录；
- 视频转音频；
- 直播截获；
- 常见问题；
- 更新日志；
- 从源码构建。

## 8. 发布后复查

### 仓库

- `main` 最新提交是本地最新源码；
- description 和 topics 正确；
- LICENSE 仍为 MIT；
- Release 标签正确；
- Release 附件可下载；
- 旧 Release 未被误删。

### 安装包

在干净目录解压下载的 zip：

1. 启动 EXE；
2. 播放；
3. 导出；
4. 转换；
5. 扫描直播；
6. 截获 10 秒；
7. 录制并合并；
8. 检查输出目录和 SHA-256。

### 文档

- README 版本、发布链接、下载包名一致；
- Wiki 版本与 EXE 一致；
- Obsidian 的 `version` frontmatter 已更新；
- FAQ 没有描述已删除的系统输出回环；
- 已知限制与新版本一致。

## 失败与回退

如果 GitHub git 端点不稳定：

- 记录失败命令和响应；
- 稍后重试；
- 不要用删除远端仓库或强制覆盖旧 Release 来“修复”；
- 检查 `api.github.com` 是否正常。

如果打包产物有问题：

- 保留源代码和版本号；
- 修复后重新构建；
- 重新生成 GitHub 包；
- 确认 Release 资源替换策略；
- 必要时发布补丁版本，不重写已发布的公共版本历史。

## 凭据清理

发布前检查：

```powershell
Get-ChildItem -Recurse -Force -File |
  Where-Object { $_.Name -match 'token|secret|credential' } |
  Select-Object FullName
```

令牌文件必须留在 `.gitignore` 和构建脚本 ignore 列表中。
