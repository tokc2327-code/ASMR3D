# 12 模块：原生捕获脚本

[[00-索引]] · 相关：[[11-模块-桌面主进程]] · [[24-功能-直播截获与录制]] · [[30-关键决策与原因]]

## 文件

```text
tools/probe_process_audio.ps1
```

约 42 KB，是 PowerShell 脚本加内嵌 C#。C# 负责调用 Windows WASAPI，PowerShell 负责参数解析、进程生命周期和 stdout 输出。

## 为什么需要它

Chromium / Electron 没有直接暴露 Windows **Process Loopback**。要按应用抓取音频，需要：

```text
ActivateAudioInterfaceAsync
  + VIRTUAL_AUDIO_DEVICE_PROCESS_LOOPBACK
  + 目标 PID
```

该接口在 .NET Framework 的 Windows PowerShell 5.1 上固定激活失败：

```text
E_ILLEGAL_METHOD_CALL (0x8000000E)
```

在 PowerShell 7（.NET Core / .NET 9）上可用。因此项目把精简版 PowerShell 7 随 EXE 内置。

## 对外模式

| 参数 | 作用 |
|---|---|
| `-ListJson` | 枚举当前活跃音频会话，输出 JSON |
| `-StreamToStdout` | 捕获目标进程树音频，输出 JSON 头 + PCM |
| `-SetVolume` | 设置目标会话音量 |
| `-GetVolume` | 读取目标会话音量 |
| `-SetMute` | 设置会话静音状态 |

### 会话列表

每条会话包含：

```text
pid, processName, displayName, peak, volume, muted, sessionIdentifier
```

列表按峰值排序，因此有声音的应用排在前面。UI 展示为：

```text
msedge · PID 30880 · -12.3 dB
```

### 流式捕获

启动参数还包括：

```text
-ProcessId <pid>
-DurationSeconds <seconds>
-SilenceTimeoutSeconds <seconds>
-StopOnProcessExit true
-OriginalVolume <value>
```

输出格式：

```text
第一行：JSON 头
后续：48000 Hz / 2 ch / float32 little-endian，交错 PCM
```

## 捕获实现要点

1. 在独立 MTA 工作线程中激活音频接口，避免 PowerShell 主线程 COM 单元干扰。
2. 用 `ActivateAudioInterfaceAsync` 完成回调等待激活结果。
3. 初始化 `IAudioClient`，格式固定为 48 kHz、双声道、float32。
4. 循环读取 render / capture 缓冲，并写入 stdout。
5. 原生脚本向 stderr 输出诊断信息，stdout 只放协议数据。
6. 设置 `[Console]::OutputEncoding`，确保 JSON 头为 UTF-8。
7. 脚本内避免非 ASCII 字面量，兼容 Windows PowerShell 的 ANSI 读取行为。

## 音量控制

“压低原声”使用会话音量，不使用设备静音。

实测行为：

| 操作 | 捕获结果 |
|---|---|
| 会话音量 `0%` | 捕获变成数字零，链路失效 |
| 会话音量 `1%` / `10%` | 捕获按同一比例精确缩小 |
| 设备级静音 | 捕获不受影响 |

因此主程序记下原音量，压到 `1%`，再在渲染链补偿 `原音量 / 0.01`。停止或退出时恢复。

## 看门狗

脚本和主进程之间需要防止音量卡在 1%：

- 正常停止时脚本由主进程发出停止信号；
- 脚本监测父进程是否仍存在；
- 父进程异常退出时，脚本尝试恢复原音量；
- 如果脚本也来不及恢复，下次启动 asmr3d 读取状态文件继续恢复。

## 为什么不用系统输出回环

系统输出回环抓的是设备最终混音，asmr3d 自己的渲染结果也在其中，会形成：

```text
捕获 → 渲染 → 耳机 → 设备混音 → 再次捕获
```

结果是多层回声和啸叫。v0.2 已彻底移除系统输出回环入口，没有 PowerShell 7 时只提示，不回退。

## 常见诊断

```powershell
# 枚举活跃会话
node tools\live_capture_smoketest.mjs --list

# 捕获 msedge 10 秒
node tools\live_capture_smoketest.mjs msedge 10

# 查看程序中实际调用的 pwsh
$env:ASMR3D_CAPTURE_LOG = 'D:\codex\asmr3d\dist\capture.log'
```

若报 `E_ILLEGAL_METHOD_CALL`，先确认实际使用的是 PowerShell 7，而不是系统 Windows PowerShell 5.1。
