# 10 模块：渲染进程

[[00-索引]] · 相关：[[02-架构与数据流]] · [[20-功能-渲染方式]] · [[22-功能-导出与分段渲染]]

## 职责

`renderer/` 是网页版和桌面版共用的界面层，也是全部音频算法的所在地。它不直接访问文件系统；桌面版通过 preload 暴露的 IPC 保存文件、打开输出目录和控制直播捕获。

## 文件

### `app.js`

主要职责：

- 全局 `state`：音频上下文、当前素材、四种模式节点、播放状态、导出状态、直播状态。
- 素材载入：内置 `materials/manifest.json`、本地文件、媒体元数据。
- 播放控制：播放、暂停、停止、循环、进度拖动、前后 10 秒。
- Web Audio 图：MediaElement、单声道下混、四条模式路径、master、limiter、monitorGain。
- 空间参数：滑块、读数、映射、模式切换、实时参数更新。
- TXT 参数模板解析与导出。
- 离线导出与实时片段捕获。
- WAV 编码器和 Blob 分片。
- 视频 / 音频转 WAV。
- 直播 PCM 接入：重采样、环形缓冲、输入电平、录制分流。

定位关键逻辑时优先按函数名搜索，而不是依赖固定行号：

```text
decodeAudioData / assertDecodableLength
startSegmentedOfflineExport
startOfflineExport
startSegmentExport
createWavBuilder / encodePcmParts / writeWavHeader
parseSpatialTemplate / applySpatialTemplate
createParametricPath / createCompatibilityPath
ensureAudioGraph / updateAudioGraph / updateModeCrossfade
convertMediaToWav
StreamingResampler / pushLiveFrames / handleLiveChunk
startLiveCapture / beginRecording / finishRecording
```

### `index.html`

布局固定为四块：

- 左栏：声音对象、渲染方式、空间参数、导出、元数据。
- 中栏：播放进度、视频转音频、空间参数读数、链路图。
- 右栏：直播截获与同步录制。
- 底部：已实现方法。

### `styles.css`

粉色强调色、插画背景、暗色蒙版、毛玻璃面板。背景图使用相对路径，桌面打包后仍可从 `app.asar` 内加载。

### `live-capture-worklet.js`

在 AudioWorklet 线程中维护环形缓冲。主线程通过端口推送交错 PCM，工作线程按 128 帧块拉取，避免 IPC 到达抖动直接传入音频图。

### `server.mjs`

开发与本机网页版服务器：

- 静态文件服务；
- 素材 API；
- OGG Range 请求；
- 移动包目录；
- 默认端口 `4173`，可通过 `PORT` 覆盖。

## Web Audio 图

```text
source
  → inputGain
  → monoInput ─┬→ hrtfPath → PannerNode(HRTF) → hrtfOutput ─┐
               ├→ parametricPath → 参数化链 → 输出 ──────────┤
               └→ compatibilityPath → 场移动 / 高度 / 距离 ─┘
                                                        ↓
                                                      master
                                                        ↓
                                                     limiter
                                                        ↓
                                                 recordTap（可选）
                                                        ↓
                                                   monitorGain
                                                        ↓
                                                    destination
```

模式切换采用短时间 `setTargetAtTime` 交叉淡化，避免切换时爆音。Bypass 通过把所有空间路径增益归零实现，只保留 master 和 limiter。

## 四种模式

| 模式 | 输入 | 核心实现 |
|---|---|---|
| `binaural` | 立体声 | 保留 L/R，整体场移动、高度 EQ、距离、混响 |
| `hrtf` | 单声道 | `PannerNode.panningModel = "HRTF"` |
| `parametric` | 单声道 | ILD、ITD、头部阴影、仰角耳廓滤波 |
| `bypass` | 原声 | 不经过空间处理 |

算法细节见 [[20-功能-渲染方式]]。

## 空间参数更新

参数由 `currentParameters()` 汇总，再经过 `updateAudioGraph()` 分发：

```text
方位角 → 场移动 / Panner 位置 / ILD / ITD / 头部阴影
仰角   → 高度 EQ / Panner 高度 / 耳廓滤波
距离   → 增益、空气吸收、近场低频、混响比例
音量   → master 输出增益
```

所有参数使用平滑时间常数更新，避免拖动滑块时产生阶跃噪声。

## 导出

### 完整文件

`startOfflineExport()`：

1. 确保音频元数据已加载；
2. 读取源文件为 `ArrayBuffer`；
3. 检查 `decodeAudioData` 的 2 GiB PCM 上限；
4. 调用 `decodeAudioData`；
5. 创建 `OfflineAudioContext`；
6. 用与实时链同构的 `buildOfflineGraph()` 渲染；
7. 编码 16-bit / 24-bit WAV；
8. 通过桌面通道或网页下载保存。

### 超长 MP3

`startSegmentedOfflineExport()` 按字节切段，每段先对齐 MP3 同步字，再逐段解码、离线渲染到 `WavBlobBuilder`，最后写一个完整 WAV 头。只有 MP3 支持这种切法。

### 实时片段

`startSegmentExport()` 从 limiter 后分流，按真实播放速度捕获 5～120 秒。它与直播同步录制互斥。

## 视频转音频

`convertMediaToWav()` 不调用 ffmpeg：

```text
File → arrayBuffer
  → AudioContext.decodeAudioData
  → AudioBuffer
  → 分块 PCM / WAV 编码
  → Blob
  → 统一输出目录
```

它使用与离线导出相同的 WAV 编码器，并在转换前检查时长、输出体积和可用内存。

## 直播接入

直播链路由以下部分组成：

```text
scanLiveTargets()
  → startLiveCapture()
  → handleLiveChunk()
  → StreamingResampler
  → pushLiveFrames()
  → AudioWorklet
  → 原有空间渲染链
```

录音分流在 `limiter` 后、`monitorGain` 前。这样：

- 实时调参会被录进成品；
- 选择“静音本地监听”时仍能录制完整的空间渲染结果。

## 模式与输入切换的不变量

- 双耳兼容保留立体声输入；HRTF / 参数化会下混为单声道。
- 切换模式时先断开旧的模式输入，再连接新的模式路径。
- 素材切换后必须更新 MediaElement、元数据和播放进度状态。
- 进度条只设置 `max` 和 `value` 的最终值，不能在拖动中反复重写属性。
- 停止播放只暂停，不清空 `currentTime`。
- 导出、转换、直播录制各自有独立忙碌状态，避免同时操作音频图。
