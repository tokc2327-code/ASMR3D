# 24 功能：直播截获与录制

[[00-索引]] · 相关：[[12-模块-原生捕获脚本]] · [[11-模块-桌面主进程]] · [[22-功能-导出与分段渲染]]

## 目标

把正在播放的直播音频实时抓进 asmr3d，走现有空间渲染链到耳机；录制是附属功能，默认关闭。

仅 Windows 桌面 EXE 可用。网页版和手机版没有这个能力。

## 完整链路

```text
目标应用的 Windows 音频会话
  → 进程回环（PowerShell 7 + WASAPI）
  → stdout：JSON 头 + float32 PCM
  → Electron 主进程解析
  → IPC
  → AudioWorklet 环形缓冲
  → 重采样
  → 空间渲染链
  → master → limiter
      ├─ 录制分流 → 分段写盘 → 合并
      └─ monitorGain → 耳机
```

## 按应用捕获

使用：

```text
ActivateAudioInterfaceAsync
  + VAD\Process_Loopback
  + 目标 PID
```

只抓目标进程树，不混入系统通知音和其它应用。

### 为什么必须 PowerShell 7

| 宿主 | 结果 |
|---|---|
| PowerShell 7 / .NET 9 | 可用 |
| Windows PowerShell 5.1 / .NET Framework | `E_ILLEGAL_METHOD_CALL (0x8000000E)` |

已经排除：

- STA / MTA / 独立 MTA 线程；
- 托管接口 / ComVisible / 手写 vtable；
- 接口参数 / 原始指针 / 委托；
- 32 / 64 位；
- 应用清单；
- 回调形式。

结论是 CLR 行为差异，必须在 .NET Core 宿主运行。

## 为什么删除系统输出回环

系统输出回环采集默认播放设备的最终混音。asmr3d 自己的输出也在这条混音里，于是形成：

```text
捕获 → 渲染 → 输出设备 → 再次捕获
```

结果：

- 单层或叠加回声；
- 梳状滤波；
- 严重时啸叫；
- 无法通过简单延迟或相位修正稳定消除。

因此 v0.2 从捕获端、界面和文档中彻底删除系统输出回环。没有 PowerShell 7 时只提示，不回退。

## 默认消回声方案

### 现象

按应用捕获时仍然可能听到：

```text
路径 A：浏览器原声 → 耳机
路径 B：浏览器音频 → 捕获 → 渲染 → 耳机
```

两者相差几十毫秒，形成单层回声。

### 实测音频引擎行为

| 操作 | 捕获结果 |
|---|---|
| 会话静音 `0%` | 捕获变成数字零 |
| 会话音量 `1%` | 捕获精确缩到 1%，即 -40 dB |
| 会话音量 `10%` | 捕获精确缩到 10%，即 -20 dB |
| 设备静音 | 捕获不受影响 |

因此会话音量是线性缩放，可以在数字域无损补回。

### 推荐：压低原声 + 渲染链补偿

```text
1. 读取目标应用当前会话音量
2. 设置为 0.01（-40 dB）
3. 渲染链乘 originalVolume / 0.01
4. 耳机只听空间渲染结果
5. 停止时恢复原音量
```

常量：

```text
SOURCE_ATTENUATION_VOLUME = 0.01
MAX_COMPENSATION_GAIN = 1000
```

这个方案不改变设备音量，不影响其它应用，并且能边听边实时拖动空间参数。

### 备选：静音本地监听

```text
monitorGain = 0
```

用户实时听到浏览器原声，但录制分流在 `monitorGain` 之前，因此录制仍写入完整的空间渲染成品。

```text
limiter → 录制分流 → monitorGain(0) → 耳机
```

不要把这些节点顺序调换。

### 音量恢复三层兜底

1. 正常停止截获时恢复；
2. 关闭窗口 / 退出应用时恢复；
3. 强制结束后下次启动读取状态文件恢复。

状态文件：

```text
%APPDATA%\asmr3d空间渲染器\source-volume-state.json
```

## 同步录制

勾选「截获时同时录制空间渲染结果」后：

```text
渲染链末端 PCM
  → 分段 WAV 写入
  → 直播结束
  → 校验所有分段
  → 流式合并为整段 WAV
  → 写 SHA-256
  → 删除临时分段
```

### 分段

| 选项 | 值 |
|---|---|
| 分段时长 | 5 / 10 / 30 分钟 |
| 位深 | 16 / 24-bit |
| 采样率 | 与 AudioContext 一致 |
| 声道 | 2 |

分段只是写盘策略，最终用户得到单个完整文件。

- 按采样点边界切；
- 段间无重叠、无空洞；
- 先写占位头，完成后回填；
- 合并流式复制 PCM 负载；
- 总长度超过约 4 GB 自动 RF64。

### 停止条件

| 条件 | 行为 |
|---|---|
| 手动停止 | 立即停止并合并 |
| 目标进程退出 | 自动停止并合并 |
| 持续静音 | 默认关闭，可选 30 / 60 / 120 秒 |

实时监听默认关闭静音自动停止，避免正常直播中的安静段落误触发。
v0.3.1 还会在捕获链路异常中断时自动重连最多 3 次。

### 输出

```text
输出\asmr3d_recording_20261004_134846.wav
输出\asmr3d_recording_20261004_134846.wav.sha256
```

临时文件：

```text
输出\asmr3d_recording_20261004_134846.part001.wav
输出\asmr3d_recording_20261004_134846.segments.json
```

只有最终文件通过长度校验后才删除分段。失败时保留分段，可重试。

## 资源占用

| 项目 | 实测 |
|---|---:|
| 进程回环捕获 | 约 3～4% 单核 |
| 24-bit 写盘 | 约 288 KB/s，约 1.04 GB/小时 |
| 录制内存 | 固定缓冲，不随时长增长 |
| 合并峰值磁盘 | 约成品大小的 2 倍 |

## 已知限制

- 仅 Windows；
- 仅按应用，不提供系统输出回环；
- DRM 内容无法捕获；
- 直播结束但浏览器不退出时，依赖静音超时或手动停止；
- 录制的是空间渲染成品，不是原始抓取 PCM；
- 如果包内 `resources/pwsh` 被删掉，截获会提示需要 PowerShell 7。
