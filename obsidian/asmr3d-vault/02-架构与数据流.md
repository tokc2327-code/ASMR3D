# 02 架构与数据流

[[00-索引]] · 相关：[[10-模块-渲染进程]] · [[11-模块-桌面主进程]] · [[12-模块-原生捕获脚本]]

## 三层结构

```text
┌─────────────────────────────────────────────┐
│ Electron 主进程 desktop/                    │
│ 窗口、IPC、输出目录、进程回环、分段录制     │
└───────────────┬─────────────────────────────┘
                │ contextBridge 白名单
┌───────────────▼─────────────────────────────┐
│ 渲染进程 renderer/                           │
│ 界面、Web Audio 图、空间算法、WAV 编码       │
└───────────────┬─────────────────────────────┘
                │ stdout PCM / IPC
┌───────────────▼─────────────────────────────┐
│ 原生捕获 tools/probe_process_audio.ps1       │
│ C# + WASAPI Process Loopback                 │
└─────────────────────────────────────────────┘
```

网页版没有 Electron 主进程和原生捕获层；它只运行 `renderer/`，因此没有直播截获。

## 普通素材的播放链

```text
内置素材 / 本地文件
  → HTMLAudioElement
  → MediaElementAudioSourceNode
  → 模式输入
      ├─ 双耳兼容：Stereo → Field pan → Elevation EQ → Distance
      ├─ 浏览器 HRTF：Mono → PannerNode(HRTF)
      ├─ 参数化 HRTF：Mono → ILD / ITD / Head shadow / Elevation EQ
      └─ Bypass：直通
  → 模式输出
  → master
  → limiter
  → monitorGain
  → 输出设备
```

限幅器固定阈值约 `-2 dB`、比率 `16:1`。它的输出点同时用于录制分流，录制分流位于 `monitorGain` 之前。

## 直播截获链

```text
目标应用音频会话
  → WASAPI Process Loopback
  → 48000 Hz / 2 ch / float32 little-endian，交错 PCM
  → PowerShell stdout
  → Electron 主进程解析
  → IPC 分块
  → AudioWorklet 环形缓冲
  → 线性插值重采样到 AudioContext 采样率
  → 空间渲染链
  → limiter
      ├─ 录音分流 → segment-recorder
      └─ monitorGain → 耳机
```

直播输入固定按 2 声道进入现有链路。渲染进程根据 AudioContext 的实际采样率重采样，因此设备是 44.1 kHz 时不会产生固定漂移。

## 关键进程边界

| 边界 | 传什么 | 谁负责 |
|---|---|---|
| 原生脚本 → 主进程 | 一行 JSON 头 + 连续二进制 PCM | `desktop/live-capture.cjs` |
| 主进程 → 渲染进程 | `ArrayBuffer` 分块与状态事件 | `desktop/preload.cjs` |
| 渲染进程 → 主进程 | 保存文件、打开输出目录、开始/停止截获、录制控制 | IPC 白名单 |
| 渲染进程 → 原生脚本 | 会话枚举、音量读写、开始/停止捕获 | `desktop/live-capture.cjs` |

渲染进程不能直接访问 Node 或文件系统，所有本地能力都要经过 preload 暴露的接口。

## 输出与状态位置

| 内容 | 位置 |
|---|---|
| 成品输出 | `<EXE目录>\输出` |
| 开发模式输出 | `dist\输出` |
| 捕获脚本 | `<EXE目录>\resources\probe_process_audio.ps1` |
| 内置 PowerShell | `<EXE目录>\resources\pwsh\pwsh.exe` |
| 会话音量恢复状态 | `%APPDATA%\asmr3d空间渲染器\source-volume-state.json` |
| 临时分段 | 输出目录内 `*.partNNN.wav` |
| 分段元数据 | 输出目录内 `*.segments.json` |

## 不变量

- 录制分流必须在 `monitorGain` 之前，否则“静音本地监听”会录出空文件。
- 会话音量压到 `0%` 会让捕获变成数字零，不能用“会话静音”实现抗回声。
- 系统输出回环不能恢复，否则会把 asmr3d 自己的输出抓回去。
- 原生捕获必须运行在 .NET Core 宿主中。
- 超长音频必须在调用 `decodeAudioData` 之前检查或分段。
