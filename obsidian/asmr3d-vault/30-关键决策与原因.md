# 30 关键决策与原因

[[00-索引]] · 相关：[[31-踩坑与修复记录]] · [[50-已知限制与后续]]

这份笔记记录已经确定的设计选择，以及为什么没有采用其它方案。后续模型接手时，优先尊重这些结论，除非有新的实测证据。

## 1. 用 Electron + Web Audio，而不是原生音频工作站

选择：

```text
Electron           跨平台窗口与 Chromium 音频能力
Web Audio API      实时图和 OfflineAudioContext
HTML / CSS / JS    界面与状态
```

原因：

- `OfflineAudioContext` 可以直接做快于实时的离线渲染；
- `PannerNode` 自带浏览器 HRTF；
- MediaElement 解码覆盖面足够广；
- 开发迭代快，网页版和桌面版共用 `renderer/`；
- 不需要 native addon，避免 Electron ABI 匹配。

代价：

- 包体被 Chromium 拉大；
- 浏览器音频能力决定格式边界；
- 不能直接访问 WASAPI，需要单独的捕获层。

## 2. 直播捕获用进程回环 + .NET Core

选择：

```text
PowerShell 7 7.6.6
  → 内嵌 C#
  → ActivateAudioInterfaceAsync
  → VAD\Process_Loopback
```

原因：

| 宿主 | 结果 |
|---|---|
| PowerShell 7 / .NET 9 | 可用 |
| Windows PowerShell 5.1 / .NET Framework 4.x | 固定失败 `0x8000000E` |

已经排除的差异因素：

- COM 单元；
- 回调对象形式；
- P/Invoke 形式；
- 32 / 64 位；
- 应用清单；
- 独立 MTA 线程。

因此没有可接受的 .NET Framework 绕过方式。为了最终用户不需要手动安装，构建时把精简版 PowerShell 7 放进 EXE。

## 3. 删除系统输出回环

早期方案抓取默认播放设备的最终混音，导致 asmr3d 自己的输出也被采集：

```text
捕获 → 渲染 → 设备输出 → 再次捕获
```

结果是多层回声，严重时啸叫。该模式已从捕获端、脚本、界面和文档中移除。

现在的规则：

- 没有 PowerShell 7 时只提示；
- 不回退到系统输出回环；
- UI 徽标“按应用”表示走的是进程回环。

## 4. 压低原声，不静音会话

实测会话音量是精确线性缩放：

```text
10% → 捕获 -20 dB
1%  → 捕获 -40 dB
0%  → 捕获成为数字零
```

选择：

```text
保存原音量
  → 会话设为 1%
  → 渲染链补偿 original / 0.01
  → 停止时恢复
```

原因：

- 原声几乎听不见；
- 捕获仍有完整信号；
- 数字补偿在 float32 中基本无损；
- 用户可以实时调整空间参数；
- 设备级音量不变，不影响其它应用。

绝不能把会话静音作为默认方案。

## 5. 录制分流放在监听之前

固定顺序：

```text
limiter
  → 录制分流
  → monitorGain
  → 耳机
```

原因：

- 录制内容等于送往耳机的空间渲染结果；
- 实时调参会记录进成品；
- “静音本地监听”时仍能录到完整成品；
- 如果放在 `monitorGain` 之后，监听静音会得到空文件。

实测方位角从 `-90°` 拖到 `+90°`，成品 L-R 差异从 `+12.79 dB` 变到 `-16.27 dB`，证明实时调参被写入。

## 6. 视频转音频不依赖 ffmpeg

选择：

```text
decodeAudioData
  → AudioBuffer
  → WAV 编码
```

原因：

- Chromium 已能解常见 MP4 / MOV / WebM / M4A；
- 便携包不需要额外发行 ffmpeg；
- 比实时播放录制快得多；
- 和现有 WAV 编码器复用。

代价：

- 不支持 MKV；
- 不支持 Chromium 没带的编码；
- 整条音轨驻留内存；
- 单次解码约 2 GiB PCM。

## 7. 超长音频只自动切 MP3

选择：

- MP3 超长时自动分段；
- FLAC、OGG、MP4 超长时给出明确提示。

原因：

| 格式 | 中段切片 |
|---|---|
| MP3 | 可解码，帧自包含 |
| FLAC | 需要 STREAMINFO |
| OGG / Opus | 需要 codec setup |
| MP4 / M4A | 需要 moov |

MP3 分段起点会对齐到同步字，段间理论损失不超过一帧，约 26 ms。

## 8. 统一输出文件夹

选择：

```text
<EXE目录>\输出
```

原因：

- 用户不需要每次选保存位置；
- 导出、直播录制、视频转换、模板导出集中管理；
- 便携版移动整个文件夹即可移动成品；
- 同名文件自动编号，避免覆盖。

不可写时再退回音乐目录或临时目录。

## 9. 参数模板用 TXT

选择：

```text
键 = 值
中英文键名
单位可写可不写
越界限幅
未知行跳过
```

原因：

- 用户可以直接用记事本修改；
- 类似均衡器预设的使用习惯；
- 非技术用户不需要 JSON；
- 导入即套用，适合重复听感实验。

## 10. 内置 PowerShell 7

选择：

```text
resources\pwsh\pwsh.exe
```

原因：

- 用户不需要安装、配置 PATH；
- 包内路径优先于系统 PATH；
- 避免系统旧版本导致 `E_ILLEGAL_METHOD_CALL`；
- 官方 244.7 MB 精简到约 192 MB，压缩约 83 MB。

风险：

- 包体显著增加；
- 精简过度会导致脚本启动失败。

所以必须保留 `ref\`、Roslyn 和必需运行文件。

## 11. Android 暂停，移动端改 PWA

原因：

- Android 工具链和第三方依赖风险尚未评估完；
- APK 当前不是核心用户场景；
- 手机系统不允许普通应用任意抓取其它应用音频；
- PWA 足以做素材试听、参数调整和导出。

Android 工程保留在 `android/`，未来可以重新评估。

## 12. 粉色主题与插画背景

最终界面使用粉色强调色、暗色蒙版和毛玻璃面板。选择原因：

- 用户明确要求把绿色改成粉色；
- 背景插画需要保证文字对比度；
- 直播截获放右栏，已实现方法放底部；
- Windows 图标使用用户提供的图像生成。

视觉变化不应影响功能控件的可用性。

## 13. 停止播放保留位置

选择：

```text
停止 = pause
currentTime 不清零
```

原因：

- 用户希望在长时间素材中原地继续；
- 进度条可以实时拖动；
- 回到开头由进度条或后退按钮完成。

## 14. 长文件先检查，再尝试解码

选择：

- 读取元数据；
- 计算 PCM 字节数；
- 计算输出大小和内存；
- 只对 MP3 启用自动分段；
- 其它格式给出中文可操作提示。

原因：

- 避免执行到一半才报 `Unable to decode audio data`；
- 让用户知道该切段、改格式还是换位深。

## 被否决 / 不采用的方案

| 方案 | 状态 | 原因 |
|---|---|---|
| Windows PowerShell 5.1 做进程回环 | 否决 | .NET Framework 固定失败 |
| 系统输出回环 | 移除 | 自激、回声、啸叫 |
| 会话音量 0% 消回声 | 否决 | 捕获变数字零 |
| 把录制分流放在监听之后 | 否决 | 静音监听会录空 |
| 依赖外部 ffmpeg | 不采用 | 增加安装和分发负担 |
| 所有格式自动中段切片 | 不采用 | 只有 MP3 可靠 |
| 从双耳录音恢复独立对象 | 不承诺 | 技术上不可靠 |
| 无提示直接拒绝超长文件 | 改进为检查 | 体验差，无法指导操作 |

## 给模型的原则

1. 不要重新引入系统输出回环。
2. 不要把会话音量设为 0% 来消除回声。
3. 不要把录制分流移到监听之后。
4. 不要把浏览器 HRTF 说成真实声源旋转。
5. 不要只改 UI 而不更新 Web Audio 状态。
6. 不要在主线程做无让出的长循环。
7. 不要在未实测的情况下扩大格式支持承诺。
