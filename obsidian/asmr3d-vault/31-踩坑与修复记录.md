# 31 踩坑与修复记录

[[00-索引]] · 相关：[[30-关键决策与原因]] · [[32-实测数据与验证]]

下面是项目开发中已经确认过的真实问题。后续模型遇到相同现象时，先按这里的“真正原因”排查，不要重复试错。

## 内置 PowerShell

| 现象 | 真正原因 | 处理 |
|---|---|---|
| `Add-Type` 报找不到 `...\ref` | 精简 PowerShell 时删掉了 `ref\` | 保留 `ref\`，它是编译引用程序集 |
| 精简后 PowerShell 启动失败，报 `LanguagePrimitives` 初始化失败 | 删除了必需运行文件，且 WPF/WinForms 删除范围过大 | 只删除 12 个 WPF/WinForms/UIAutomation 文件 |
| 改了包内路径仍调用系统 pwsh | `resolvePowerShell()` 的 PATH 查找排在包内路径前 | 包内路径优先后，再查 PATH |

## 原生捕获

| 现象 | 真正原因 | 处理 |
|---|---|---|
| 进程回环固定返回 `0x8000000E` | Windows PowerShell 5.1 的 .NET Framework 调用不兼容 | 使用 PowerShell 7 / .NET Core |
| `-MuteState true` 传参失败 | `-File` 参数是 string，`[bool]` 绑不上 | 参数改成 `[string]`，脚本内自行解析 |
| PowerShell 中文乱码 | PS 5.1 按 ANSI 读取无 BOM 的 `.ps1` | 脚本不放非 ASCII 字面量，并设置输出编码 |
| 内嵌 C# 编译失败 | 使用 C# 7 语法，且 CodeDom 引用缺失 | 写 C# 5 兼容代码，直接 `Add-Type -TypeDefinition` |
| 截获列表出现 asmr3d 自身 | 自身也有音频会话 | 枚举时过滤自身进程，避免自反馈 |
| 中文进程名显示乱码 | stdout 编码不一致 | 设置 `[Console]::OutputEncoding` 为 UTF-8 |

## 音频播放与进度

| 现象 | 真正原因 | 处理 |
|---|---|---|
| 进度条只能点击，不能平滑拖动 | `input` 事件反复改写 `max` 会打断 Chromium 拖拽 | 只在真正变化时设置 `max` / `value`，拖动中只更新文字 |
| 停止后进度归零 | 停止按钮里写了 `currentTime = 0` | 停止改为 pause，保留当前位置 |
| 选完文件直接导出读不到时长 | 音频元素尚未挂源，`ensureAudioGraph()` 要播放后才创建 | 导出前 `src/load()` 并等待 `loadedmetadata` |
| 拖动进度没反应 | 文件未加载，进度条仍禁用 | 元数据完成后才启用 |
| AudioContext 显示 suspended | 浏览器要求用户交互后才允许放声 | 任意点击页面恢复 |

## 长音频与导出

| 现象 | 真正原因 | 处理 |
|---|---|---|
| 长音频报 `Unable to decode audio data` | `decodeAudioData` 单次最多约 2 GiB PCM | 前置时长检查，MP3 自动分段，其它格式明确提示 |
| 每段仍解码失败 | 切片点不在 MP3 帧边界 | 向后搜索 `0xFFEx` 同步字 |
| 大文件转换时窗口假死 | WAV 编码是同步长循环 | 每 64 K 帧 `await` 让出主线程 |
| 导出文件巨大 | 24-bit WAV 是未压缩 PCM | 告知体积，建议 16-bit 或保留源 MP3 |
| 用户问为什么 MP3 转 WAV 大很多 | 306 kbps MP3 vs 24-bit 48 kHz 约 2304 kbps | 差距约 7.5 倍，这是 PCM 未压缩的必然结果 |

## 文件系统与桌面主进程

| 现象 | 真正原因 | 处理 |
|---|---|---|
| 输出到 `D:\` 报 `EPERM mkdir` | Node 对已存在的盘符根目录调用 `mkdirSync` 仍可能抛错 | 先判断存在，再做可写性探测 |
| EXE 放在不可写目录 | 无法创建同级 `输出` | 回退到音乐目录，再回退临时目录 |
| 同名导出覆盖 | 之前直接覆盖 | 自动追加 `-1`、`-2` |
| 选文件后转换按钮不能点 | 重构时漏了解除 disabled | 选择文件后显式启用 |

## 界面与资源

| 现象 | 真正原因 | 处理 |
|---|---|---|
| 换了 EXE 图标但资源管理器不变 | Windows 图标外壳缓存 | 重启资源管理器或清理 IconCache |
| 整页截图背景错位 | `background-attachment: fixed` 与 `captureBeyondViewport` 冲突 | 属截图假象，视口截图正常 |
| 手机上文字溢出或按钮错位 | 桌面布局直接缩窄 | 移动端使用单独布局和响应式约束 |
| 绿色主题残留 | 用户要求粉色 | 扫描 CSS 色值并统一替换 |

## 直播回声与音量

| 现象 | 真正原因 | 处理 |
|---|---|---|
| 耳机能同时听到原声和渲染结果 | 两条路径叠加，相差几十毫秒 | 压低原声 + 渲染链补偿 |
| 改成会话静音后没有声音 | 会话 0% 会让捕获变数字零 | 不使用会话静音 |
| 录到的不是空间结果 | 录制分流位置错误 | 固定在 limiter 后、monitorGain 前 |
| 打开录制的音频发现调参没有生效 | 录制点在监听之后或录制的是原始抓取 | 录制应取渲染链末端 |
| 关闭监听后录制为空 | 分流放在了 monitorGain 之后 | 把分流移回监听之前 |
| 旧版出现多层回声 / 啸叫 | 系统输出回环把自身输出抓回去 | v0.2 彻底删除该模式 |

## 环境与硬件

| 现象 | 真正原因 | 处理 |
|---|---|---|
| 耳机有轻微电流音，换文件也出现 | 系统音频栈或驱动状态异常，不一定是应用处理链 | 用户实测重启后解决 |
| Windows 声音设置不能选其它 Hz | 蓝牙 / USB 音频端点只暴露固定格式，或驱动未提供 | 在设备属性中检查支持的默认格式，必要时换独占模式或更新驱动 |
| 有线耳机仍有电流音 | 排除蓝牙后需检查接口、线材、采样率、驱动和系统增益 | 逐项隔离，先确认源文件本身是否正常 |
| 进度提示音后有电流音 | 系统会话切换或驱动状态问题 | 用户重启后解决 |

## 版本与发布

| 现象 | 真正原因 | 处理 |
|---|---|---|
| 界面显示 v0.2，压缩包还是 v0.1 | 版本字符串散落在多个文件 | 用 `bump_version.mjs` 统一替换 |
| 发布包泄露令牌 | 打包脚本不读 `.gitignore` | 在打包脚本 ignore 列表中加入凭据文件 |
| GitHub git 推送不稳定 | `github.com:443` 端点偶发失败 | 用 `api.github.com` 相关脚本重试，或稍后再推 |
| 网页上直接修改被覆盖 | 上传脚本 force push | 发布前以本地源码树为准，避免网页端直接改 |

## 排查原则

1. 先确认问题出现在哪一层：源文件、系统音频栈、捕获、Web Audio、导出、文件系统。
2. 用 `node tools/inspect_wav.mjs` 检查输入和输出，而不是只靠听感。
3. 直播问题先确认实际运行的是不是包内 PowerShell 7。
4. 超长文件先确认时长和格式，再决定是否能自动分段。
5. 任何涉及会话音量的改动，都要测试停止恢复、退出恢复和强制结束后恢复。

更多量化数据见 [[32-实测数据与验证]]。
