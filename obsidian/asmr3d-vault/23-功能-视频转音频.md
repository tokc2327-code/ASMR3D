# 23 功能：视频转音频

[[00-索引]] · 相关：[[22-功能-导出与分段渲染]] · [[50-已知限制与后续]]

## 功能

在界面中栏「音频播放进度」下方选择一个视频或音频文件，抽出音轨并写成 WAV，输出到统一 `输出` 文件夹。

用途：

- 把 MP4 / MOV / WebM 中的 ASMR 音轨提取出来；
- 转成 WAV 后重新导入 3D 渲染链；
- 避免用户为了一个简单抽取动作额外安装 ffmpeg。

## 不依赖 ffmpeg

实现：

```text
File
  → arrayBuffer
  → AudioContext.decodeAudioData
  → AudioBuffer(float32)
  → 16-bit / 24-bit WAV 编码
  → Blob
  → 输出目录
```

解码器来自 Electron / Chromium 自带能力，因此支持范围与浏览器一致，而不是与 ffmpeg 一致。

## 操作流程

1. 点「选择文件」；
2. 程序只读容器元数据，立即显示：

```text
某视频.mp4 · 1:03:41 · 源文件 355.2 MB
→ 预计输出 1.02 GB（24-bit），转换需要约 1.71 GB 内存
```

3. 选 16-bit 或 24-bit；
4. 点「转换为 WAV」；
5. 进度分为解码和编码两个阶段；
6. 完成后显示文件名、时长、声道、采样率、位深和体积。

## 支持范围

### 支持

| 封装 / 编码 | 说明 |
|---|---|
| MP4 / M4V / MOV | H.264 + AAC 等常见组合 |
| WebM | VP8 / VP9 + Opus / Vorbis |
| M4A / AAC | 纯音频 |
| MP3 / FLAC / WAV / OGG | 纯音频也可走这个入口 |

### 不支持

| 类型 | 原因 |
|---|---|
| MKV | Chromium 不支持该封装 |
| H.265 / AC3 / DTS 等 | 内置解码器覆盖不到 |
| DRM 内容 | 无法解密 |
| 损坏文件 | 解复用或解码失败 |

失败时不会留下半成品。

## 为什么不是实时

常见做法是播放一遍再录，1 小时视频就要 1 小时。本功能直接把完整音轨解码为 PCM，再写 WAV，因此是秒级：

```text
355 MB / 63.7 分钟 H.264 + AAC MP4
→ 1024 MB / 24-bit WAV
→ 14.5 秒
  ├─ 解码约 7 秒
  └─ 编码约 6 秒

26 秒小文件 → 0.5 秒
```

代价是整条音轨的 float32 PCM 需要驻留内存。

## 内存与时长的三项检查

| 检查 | 阈值 | 超出时 |
|---|---|---:|
| 单次解码 PCM | 约 2 GiB，48 kHz 立体声约 93 分钟 | 拒绝并提示切段 |
| 输出 WAV | 3.8 GB | 拒绝，RIFF 长度限制 |
| 预计峰值内存 | 当前可用内存 × 85% | 提示关闭其它程序 |

估算公式：

```text
decoded = duration × 48000 × 2 × 4
wav = duration × 48000 × 2 × (bitDepth / 8)
peak = decoded + 源文件大小
```

位深只影响输出大小，不影响解码缓冲；内存不足时改 16-bit 没有帮助。

## 进度与响应

- 读取元数据只加载容器头部，不扫描整文件；
- 解码阶段占主要内存和 CPU；
- WAV 编码按 64 K 帧分块；
- 每块定期让出主线程，因此转大文件时窗口不假死；
- 编码临时数据放入 Blob 分片，避免再复制一份等价大小的 PCM。

## 输出

```text
<原文件名去扩展名>.wav
```

写入统一输出目录，同名自动加序号。转换结果可以再次用「导入本地文件」进入渲染链。

## 建议

- 只要音轨时，优先直接使用原始 FLAC / WAV；
- MP4 里的 AAC 是有损压缩，转 WAV 只是换容器，不会恢复丢失的信息；
- 超过限制时先切成几段，再分别转换；
- 不要用这个入口处理 MKV，先转封装成 MP4 或提取音轨。
