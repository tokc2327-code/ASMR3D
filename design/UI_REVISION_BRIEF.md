# asmr3d UI v2.1 修改交接单

这份文档交给 UI 设计 Agent。目标不是推翻现有 v2 原型，而是在现有成果上做一次定向修订：吸收 `ErgouTreeCrypt` 的紧凑、平坦、文字驱动特点，同时保留 asmr3d 的三栏实时工作流和强状态反馈。

---

## 1. 必须先读

1. `design/REDESIGN.md`
2. `design/prototype/README.md`
3. `design/prototype/index.html`
4. `design/prototype/styles.css`
5. `design/prototype/enhance.js`
6. `renderer/app.js`，只读，用于核对 DOM 契约
7. `desktop/main.cjs`，只读，用于确认窗口形态

---

## 2. 参考产品分析

参考应用 `ErgouTreeCrypt` 的设计特征：

- 纯白或近白背景，视觉非常轻。
- 顶部紧凑，品牌只占左上角。
- 一级导航和二级功能都是横排文字标签。
- 当前项主要靠字重、蓝色文字和位置表示。
- 功能之间几乎没有卡片、阴影和装饰。
- 信息密度高，适合重复使用。

它的优点：

- 紧凑，内容区占比高。
- 视觉噪声低，长期使用不累。
- 横向文字导航简洁。

它的缺点：

- 一级导航和二级功能层级区分偏弱。
- 选中态只靠颜色，不够明确。
- 点击区域和焦点态从截图无法判断。
- 状态反馈偏弱，不适合实时音频和直播录制。

---

## 3. 总体方向

保留 asmr3d 当前的：

- 粉色品牌强调色。
- 深色背景和插画底图。
- 左、中、右三栏实时工作区。
- 中栏播放、参数读数、视频转换。
- 右栏直播截获和同步录制。
- 底部状态栏。

借鉴 `ErgouTreeCrypt` 的：

- 更紧凑的顶栏。
- 更平坦的分区。
- 更少的卡片、模糊、阴影和装饰。
- 横向文字标签的轻量导航方式。
- 更克制的强调色使用。

最终形态应该是：

```text
暗色版 ErgouTreeCrypt 的紧凑外壳
++
asmr3d 的三栏实时工作台
++
更强的状态、错误和录制反馈
```

不要把它改成白色应用，也不要把它改成以顶部 Tab 为主的单栏页面。

---

## 4. 硬约束

### 不可修改

- `renderer/app.js`
- `desktop/*.cjs`
- IPC 协议
- Web Audio 链路
- 直播捕获逻辑
- 音频算法和参数范围

### 必须保留

- 81 个现有 `elements` 绑定和对应 ID。
- `#modeControl` 内 4 个模式按钮及顺序：
  `binaural`、`hrtf`、`parametric`、`bypass`。
- `.method-list` 的 12 个方法项。
- `#templateFileInput` 的 `hidden`。
- `#progressRange` 的动态 `min/max/step`。
- `#signalChain`、`#liveModeBadge`、`[data-state]` 等既有钩子。
- 播放进度可拖动。
- 停止播放后不归零。
- 直播截获和录制始终是可见的主功能。

### 窗口形态

当前 `BrowserWindow` 使用原生 Windows 窗口框：

```text
width: 1440
height: 960
minWidth: 390
minHeight: 700
```

没有设置 `frame:false`，也没有自定义标题栏。

因此：

- 不要在 HTML 中新增最小化、最大化、关闭按钮。
- 不要模拟 Windows 系统标题栏。
- 应用内顶栏是原生标题栏下面的工具条。
- 如果未来要做无边框窗口，必须单独立工程任务修改 `desktop/main.cjs`，本 UI 任务不处理。

## 5. 具体修改方案

### 5.1 顶栏

目标高度：`42-48px`。

布局：

```text
左：Logo + 产品名 + 低对比度版本号
右：引擎状态 + 输出文件夹
```

要求：

- 版本号弱化，不要和引擎状态抢视觉。
- “输出文件夹”使用图标 + 文字，保持常驻可发现。
- 引擎状态用小型胶囊，包含待机、运行中、错误三个语义。
- 去掉不必要的顶部大标题和大面积毛玻璃。
- 不要加语言切换、窗口控制或登录按钮。

### 5.2 三栏布局

继续使用三栏，三栏独立滚动：

```text
左栏：素材、渲染、空间参数、模板、导出、元数据
中栏：播放进度、视频转音频、空间参数读数、信号链
右栏：直播扫描、截获、原声处理、同步录制
底部：状态栏
```

修改要求：

- 中栏播放面板保持 sticky。
- 左栏和右栏不能因为内部内容过多而把整页滚动。
- 1280×720 下允许左右栏内部滚动，但不能隐藏核心播放和直播状态。
- 不要把右栏直播截获改成需要切换的二级页面。

### 5.3 面板层级

借鉴参考产品的“平铺但不混乱”，减少视觉容器数量：

- 左栏不要呈现为 7 个同权重大卡片。
- 优先采用一个连续面板 + 章节标题 + 分隔线。
- 导出、模板、元数据可折叠。
- 中栏每个模块最多一层边框。
- 禁止卡片套卡片。
- 面板圆角控制在 `7-10px`。
- 阴影只用于 Toast、抽屉和滑杆拇指，不给普通面板加投影。
- 降低 backdrop blur 强度，避免所有区域都像玻璃卡片。

### 5.4 导航和标签

参考产品用横排文字标签，asmr3d 只借鉴它的层级表达，不照搬页面结构：

- 不做“历史 / 日志 / 设置”顶层页面，除非产品另有明确需求。
- 在面板内部可以使用横向标签，例如导出范围、位深、录制分段。
- 一级章节标题使用图标 + 标题 + 可选徽章。
- 二级选项使用分段按钮或下划线标签。

选中态不能只靠颜色：

```text
文字变色
++
下划线或浅色底
++
字重变化
```

### 5.5 渲染方式

保留四个选项：

```text
双耳兼容（推荐）
浏览器 HRTF
参数化 HRTF
Bypass
```

要求：

- “双耳兼容”必须最左。
- 使用 2×2 分段按钮或四个并列按钮。
- 当前项有明显选中背景和描边。
- “推荐”是角标，不占按钮主标题。
- 说明文字最多一行，超出时使用 tooltip，不拉高整个面板。

### 5.6 空间参数

每个参数行固定为：

```text
标签 + 可编辑数值 + 单项复位
滑杆
最小值 / 中点 / 最大值
```

要求：

- 数值点击后可键入精确值。
- `Shift + 方向键` 为大步进，普通方向键为单步。
- 滑杆 thumb 至少 14px，轨道要能显示已填充部分。
- 距离使用对数映射，显示单位 `m`。
- 方位角和仰角显示 `°`。
- 复位按钮使用图标，不使用一整行文字按钮。

### 5.7 播放区

播放区是主操作区，优先级高于工具面板：

- 当前时间比总时长更醒目。
- 进度条高度和可拖动区域要足够大。
- 播放、暂停、停止、后退 10 秒、前进 10 秒使用图标按钮。
- 循环使用 toggle chip。
- 无素材时，暂停和停止禁用，并提供明确空态。
- 播放中有稳定状态点，但不要做夸张动画。

### 5.8 视频转音频

它是低频工具，不能压过播放区：

- 保持在中栏播放区下方。
- 可折叠，默认展开。
- 文件选择、预估信息、位深、转换按钮分层。
- 超长、编码不支持、内存不足必须在开始前显示。
- 转换中显示蓝色进行态，不锁死整个应用。

### 5.9 直播截获与录制

这是桌面版核心差异功能，不能弱化：

- 右栏顶部固定显示截获模式徽章。
- 扫描、来源选择、开始、停止是清晰主路径。
- 电平表是独立视觉模块。
- 原声处理的选择必须明确解释“压低原声”和“静音本地监听”。
- 录制开关、分段、位深、静音停止按操作顺序排列。
- 录制中显示时长、体积、分段数。
- 合并中使用进行态，不能误显示为完成。
- 保存位置和打开输出目录要常驻，不要藏在折叠区。

### 5.10 状态与错误

状态色建议：

```text
待机：灰
进行中：蓝
成功：粉
警告：琥珀
失败：红
```

每个状态必须同时有：

```text
颜色 + 图标 + 文字
```

错误处理：

- 行内错误保留。
- 同时触发右下角 Toast。
- 8 秒自动消失，可手动关闭。
- `PowerShell 7 缺失`、`设备不可用`、`无截获来源`、`权限不足`、`输出目录不可写`都必须是独立状态。
- 错误不能只改一行小字颜色。

### 5.11 底部状态栏

状态栏保持 30-36px：

```text
左：当前状态
中：AudioContext、采样率、延时
右：方法说明入口
```

方法说明保留抽屉形式，但按钮必须有明确标签和数量。

### 5.12 颜色与视觉

- 粉色只用于主按钮、当前选项、焦点环和成功态。
- 琥珀只用于数值读数。
- 蓝色只用于进行中。
- 红色只用于失败和停止。
- 不出现大面积绿色。
- 文本对比度至少达到 WCAG AA。
- 不使用装饰性渐变球、光斑、悬浮光晕。
- 背景插画保留，但降低干扰，让面板文字始终清楚。

### 5.13 字体与密度

- 使用 `Segoe UI Variable`、`Microsoft YaHei UI` 系统字体栈。
- 时间、参数、遥测使用等宽数字。
- 正文 12-13px，标题 12.5-14px，主时间 20-22px。
- 控件高度建议 30-34px。
- 标签和数值使用 tabular numbers，避免跳动。
- 不通过缩小字体来换取空间。

### 5.14 响应式与缩放

必须测试：

```text
1280×720
1440×900
1536×864
1920×1080
```

要求：

- 不出现水平滚动。
- 不出现文字溢出、遮挡和换行错位。
- 125% 和 150% 缩放下按钮和文字仍可读。
- 右栏在窄宽度下不能挤压中栏播放控制。

## 8. 验收标准

视觉上：

- 更像紧凑的桌面工具，不像 Web Dashboard。
- 面板层级更平，不依赖大量玻璃卡片。
- 粉色更克制，状态更明确。
- 顶栏和状态栏不再浪费纵向空间。

交互上：

- 核心流程不增加点击步骤。
- 播放、调参、直播状态始终可见。
- 选中态、禁用态、错误态不会混淆。
- 键盘焦点和快捷键可用。

工程上：

- `app.js` 零改动。
- 81 个 ID 无缺失。
- 无重复 ID。
- 无水平溢出。
- 原型服务器可运行。
- 交接文档说明如何进入 EXE。
