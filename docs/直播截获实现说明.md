# 直播截获与同步录制：实现说明（v0.2）

## 目标

把"实时抓取直播音频 → 走 asmr3d 空间渲染 → 耳机监听"落地到本地 EXE，
并把长时间录制做成可选的附属功能。

主功能是实时监听，录制默认关闭，不阻塞监听链。

## 运行链路

```text
目标应用的 Windows 音频会话
        ↓ 进程回环（按应用，PowerShell 7）
        ↓ 交错 float32 PCM（stdout 流）
Node / Electron 主进程
        ↓ IPC
渲染进程（Web Audio）
├── 环形缓冲 → 空间渲染 → 耳机
└── 渲染链末端分流 → 分段写盘
```

## 截获模式：只保留按应用（进程回环）

按应用截获使用 Windows 的 **Process Loopback**
（`ActivateAudioInterfaceAsync` + `VAD\Process_Loopback`），可以只抓取
指定应用进程树的音频。

这一模式需要 PowerShell 7。原因是实测发现：

| 运行宿主 | 进程回环 |
|---|---|
| PowerShell 7（.NET 9） | 可用 |
| Windows PowerShell 5.1（.NET Framework 4.x） | 不可用 |

在 .NET Framework 下，`ActivateAudioInterfaceAsync` 对进程回环激活
固定返回 `E_ILLEGAL_METHOD_CALL (0x8000000E)`。已验证与以下因素无关：

- COM 单元（STA / MTA、独立 MTA 工作线程）
- 回调对象形式（托管接口、顶层 ComVisible 类、手写非托管 vtable）
- P/Invoke 形式（接口参数、原始指针、GetProcAddress + 委托）
- 进程位数（32/64 位）、应用清单（Windows 10 supportedOS）

早期版本在缺少 PowerShell 7 时会退回**系统输出回环**（采集默认播放设备
的最终混音）。该模式会把 asmr3d 自己的输出一起抓回去，形成自激回路，
表现为多层回声甚至啸叫，因此**已从产品中移除**：

- 捕获端不再提供系统回环入口；
- 界面不再生成"系统输出"目标；
- 没有 PowerShell 7 时，扫描后状态栏直接提示"需要 PowerShell 7"，
  并给出版本/路径信息，而不会退回到会啸叫的模式。

界面上扫描成功后显示"按应用"，即表示走的是进程回环。

## 采集格式

```text
48000 Hz / 2 ch / float32 little-endian（交错）
```

渲染进程用线性插值把采集采样率重采样到 AudioContext 采样率，因此
输出设备是 44.1 kHz 时也不会产生漂移。

## 模式 C+：分段持续录制

```text
直播开始
→ 实时空间渲染
→ 按固定时长连续分段写入
→ 直播结束（手动 / 进程退出 / 持续静音）
→ 校验全部分段（声道、采样率、位深、长度一致）
→ 合并为整段 WAV
→ 校验文件长度并写入 SHA-256
→ 删除临时分段
```

实现要点：

- 分段只是临时写入单位，用户最终得到单个完整音频；
- 以采样点边界切段，段间无重叠、无空洞；
- 每段写入前先落占位头，写满后回填真实长度；
- 合并时流式复制 PCM 负载，内存占用与录音时长无关；
- 总量超过约 4 GB 时自动输出 RF64，避免 RIFF 长度上限；
- 只有合并文件写完并通过长度校验后才删除分段；
- 合并失败时保留全部分段，允许重试。

文件名示例：

```text
<程序目录>\输出\asmr3d_recording_20261004_134846.wav
<程序目录>\输出\asmr3d_recording_20261004_134846.wav.sha256
```

临时分段与元数据：

```text
<程序目录>\输出\asmr3d_recording_20261004_134846.part001.wav
<程序目录>\输出\asmr3d_recording_20261004_134846.segments.json
```

## 空间参数模板（TXT 导入 / 导出）

左侧"空间参数"面板底部有 **参数模板（TXT）**：导入一个 TXT 就立即套用，
导出则把当前参数写成同格式的 TXT（同样落在输出文件夹）。

导出的文件长这样，本身就是可用模板：

```text
# asmr3d空间渲染器 · 空间参数模板 v1
# 每行一个参数，用 = 或 : 分隔；# // ; 开头的行是注释
# 数值可带单位，例如 0.4 m、80%、-12.5°

模板名称 = Food - Eating a fruit
方位角 = 30.0
仰角 = 12.0
距离 = 1.53
输出音量 = 66
渲染方式 = parametric
```

解析规则（按均衡器 EQ 文件的习惯来）：

| 规则 | 说明 |
|---|---|
| 分隔符 | `=`、`:`、`：` 都可以 |
| 注释 | `#`、`//`、`;` 开头的行整行忽略 |
| 键名 | 中英文均可：`方位角`/`azimuth`、`仰角`/`elevation`、`距离`/`distance`、`输出音量`/`volume`、`渲染方式`/`mode` |
| 数值 | 自动去掉单位：`0.4 m`、`80%`、`-12.5°` 都能识别 |
| 越界 | 自动限幅（方位角 ±90°、仰角 ±30°、距离 0.2–10 m、音量 0–100%）并在状态里说明 |
| 未知行 | 跳过并提示忽略了几行，不会整体失败 |

渲染方式支持 `binaural` / `hrtf` / `parametric` / `bypass`，也接受
`双耳兼容`、`浏览器HRTF`、`参数化HRTF`、`Bypass` 这类写法。

导入后会立刻更新滑块、读数、声像和渲染链，不需要按播放。

## 视频转音频（本地抽取音轨）

界面中间"音频播放进度"下方有 **视频转音频** 面板：选一个视频或音频文件，
点"转换为 WAV"，音轨会被抽取并写成 WAV 放到同一个输出文件夹。

实现方式：不依赖外部 ffmpeg，直接用 Chromium/Electron 自带的解复用与解码
能力（`AudioContext.decodeAudioData`），再把解码结果编码成 16/24-bit PCM。

- 实测：355 MB、63.7 分钟的 H.264 + AAC MP4 → 1024 MB 的 24-bit WAV，
  用时 **14.5 秒**（解码约 7 秒 + 编码约 6 秒），不需要实时播放，也不占用耳机输出；
- 26 秒的小文件用时 0.5 秒；编码分块并定期让出主线程，长文件转换时窗口不卡死；
- 支持 Chromium 能解的封装：MP4 / M4V / MOV / WebM / M4A / AAC / FLAC /
  WAV / MP3 / OGG；MKV 不在支持范围（Chromium 不支持该封装）；

### 时长上限与内存

`decodeAudioData` 会把整条音轨解码成 float32 PCM 常驻内存，所以真正的天花板
是**可用内存**而不是固定时长。程序在选中文件后就会先读容器元数据，并给出预估：

```text
羊娘めめ …mp4 · 1:03:41 · 源文件 355.2 MB
→ 预计输出 1.02 GB（24-bit），转换需要约 1.71 GB 内存
```

转换前的三条硬性检查：

| 检查 | 阈值 | 说明 |
|---|---|---|
| 时长 | 6 小时 | 绝对上限，超过直接拒绝 |
| 输出 WAV | 3.8 GB | RIFF 的 4 GB 长度字段限制 |
| 预计内存 | 可用内存 × 85% | 超出时提示关闭其他程序 |

内存估算 = 解码 PCM（时长 × 48000 × 2 × 4 字节）+ 源文件大小。实测 63.7 分钟
的文件峰值约 1.7 GB，普通 16 GB 机器可以直接转换。

WAV 编码按 64 K 帧分块拼成 Blob，长文件不会在解码缓冲之外再产生一份等大的
中间缓冲区。

## 统一输出文件夹

所有成品音频（离线导出、片段导出、直播录制合并结果）默认都写入
**EXE 同级目录下的 `输出` 文件夹**，不再弹出保存对话框：

```text
asmr3d-v0.3-win-x64\
├── asmr3d空间渲染器.exe
└── 输出\
    ├── asmr3d_recording_20261004_152644.wav
    └── asmr3d_recording_20261004_152644.wav.sha256
```

- 文件夹不存在时自动创建；同名文件自动加 `-1`、`-2` 后缀，不会覆盖；
- 界面里的"打开输出文件夹"按钮直接打开它；"更改保存位置"可以临时改到别处；
- 如果 EXE 所在位置不可写（例如放在受保护目录），会自动退回到
  `音乐\asmr3d输出`，再不行退到系统临时目录；
- 开发模式（`electron desktop/main.cjs`）下输出到项目的 `dist\输出`。

## 停止条件

1. 用户点击"停止截获"：立即停止并合并。
2. 目标进程退出：自动停止并合并。
3. 持续静音达到设定时长（30 / 60 / 120 秒，可关闭）：自动停止并合并。

## 多声道 / 立体声

进程回环固定输出 2 声道，渲染进程直接进入现有链路。

## 需要注意

- 受 DRM 保护的内容无法捕获；
- 只抓取所选应用，其他应用的通知音不会被录进去；
- 录制的是**已经空间渲染**的成品，不是原始抓取数据。

## 回声 / 啸叫怎么解决

### 唯一剩下的来源：原声与渲染结果叠加

按应用截获下，浏览器原声（路径 A）与 asmr3d 渲染结果（路径 B）会同时
送到耳机，两条路径相差几十毫秒，形成单层回声或梳状滤波。

自激回路（多层回声、啸叫）来自旧的系统输出回环模式：它把 asmr3d 自己
的输出也抓了回去。该系统模式**已从产品中删除**，因此不会再出现。

### 实测结论（决定了解法）

| 操作 | 对进程回环捕获的影响 |
|---|---|
| 会话级静音（音量 0%） | 捕获同时变成静音，不可用 |
| 会话级降低音量（1% / 10%） | 捕获按相同比例缩小，**精确线性** |
| 设备级静音（把整个输出设备静音） | 捕获不受影响，仍有信号 |

关键点：**会话音量是线性的**，而且音量降到 0 时输出是真正的数字零，
说明这条路径没有引入额外噪声。因此在渲染链里补回同样的增益是无损的。

### 默认方案：压低原声 + 渲染链补偿（推荐）

界面里的"原声处理"选择 **"压低原声（实时听渲染，推荐）"**，程序会：

1. 记下目标应用当前的会话音量；
2. 把它的会话音量压到 `0.1%`（−60 dB），原声因此几乎听不见；
3. 在渲染链里乘上 `原音量 ÷ 0.001` 的补偿增益，上限为 +66 dB；
4. 停止截获时把会话音量恢复原值（退出程序也会兜底恢复）。

这样耳机里听到的只有空间渲染结果，仍然可以实时拖动方位角、仰角、
距离和音量，回声消失，而且不损失精度（补偿是在 float32 里做的）。

该方案要求走**按应用截获**（需要 PowerShell 7）。

音量恢复由三层保障：

```text
停止截获        → 立即恢复
关闭窗口 / 退出 → 恢复（退出前等待完成）
主程序被强制结束 → 下次启动时自动恢复（状态存在 userData\source-volume-state.json）
```

实测：截获中原声音量为 `0.001`；正常停止后为 `1.0`；强制结束主进程后
再次启动 asmr3d，音量自动回到 `1.0`。

### 备选方案一：分离输出设备（不做增益补偿）

如果不想改动会话音量，也可以把原声送到另一个输出设备：

1. 打开"设置 → 系统 → 声音 → 音量合成器"，把浏览器（msedge / chrome）
   的输出设备改成**不是耳机**的另一个设备，例如主板扬声器或 HDMI；
2. 把这个原声设备整体静音（设备级静音不会影响按应用截获）；
3. asmr3d 保持输出到耳机。

结果同样是耳机里只有渲染结果，而且完全不动会话音量。

### 备选方案二：静音本地监听（只听原声）

把"原声处理"选为 **"静音本地监听（只听原声）"**：asmr3d 不再向耳机
输出渲染结果，因此没有叠加也没有自激；实时听到的是浏览器原声，
同步录制仍然写入已经空间渲染的成品。该静音节点位于录制分流之后，
所以只影响监听，不影响录制内容。

### 安装 PowerShell 7

没有 PowerShell 7 时截获功能不可用（程序会明确提示，而不是退回到会
啸叫的旧模式）。安装方式：

```powershell
winget install --id Microsoft.PowerShell --source winget
```

没有管理员权限时，可以用用户级安装（不弹 UAC）：把官方
`PowerShell-<版本>-win-x64.zip` 解压到
`%LOCALAPPDATA%\Programs\PowerShell\7\`。程序不依赖 PATH，会自动查找：

```text
%ProgramFiles%\PowerShell\7\pwsh.exe
%ProgramFiles%\PowerShell\7-preview\pwsh.exe
%ProgramFiles(x86)%\PowerShell\7\pwsh.exe
%LOCALAPPDATA%\Programs\PowerShell\7\pwsh.exe
%LOCALAPPDATA%\Microsoft\WindowsApps\pwsh.exe
```

装上并重启 asmr3d 后，扫描音频应用时右上角显示"按应用"，即表示已经
切到进程回环。
