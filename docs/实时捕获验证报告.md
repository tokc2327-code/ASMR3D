# 实时抓取直播音频验证报告

## 测试目标

验证以下流程：

```text
Twitch 在 Edge 中正常播放
→ Electron 启动系统音频捕获
→ loopbackWithMute / loopback
→ 捕获链获得音频
→ 原始声音从本地扬声器抑制
→ 处理结果输出到耳机
```

## 测试环境

- Windows 11 24H2
- Edge 正在播放 Twitch 直播
- 默认输出设备：OPPO Enco Air5 Pro
- 输出格式：48 kHz / 2 channels
- Electron 44.5.1
- 音频预处理：关闭 AGC、降噪和回声消除

## 系统输出验证

WASAPI 默认输出回环测量：

| 输出角色 | 峰值 | RMS | 结果 |
|---|---:|---:|---|
| Console | -18.5 dBFS | -40.1 dBFS | 有音频 |
| Multimedia | -21.1 dBFS | -42.2 dBFS | 有音频 |
| Communications | -21.1 dBFS | -42.2 dBFS | 有音频 |

因此 Twitch 音频确实进入了系统默认输出端点。

## Electron 捕获验证

| 捕获模式 | 输入峰值 | 结果 |
|---|---:|---|
| Electron loopbackWithMute | -∞ dBFS | 未捕获到 Twitch |
| Electron loopback | -75.5 dBFS | 只有底噪，没有有效 Twitch 音频 |
| Electron loopback + Electron 自身测试音 | -26.0 dBFS | 捕获成功 |
| Electron loopback + 独立 Windows 进程测试音 | -19.8 dBFS | 捕获成功 |

## 结论

Electron `desktopCapturer` 的系统回环捕获在这台机器上可以捕获：

- Electron 自身播放的测试音；
- 独立的 Windows 进程测试音。

但不能捕获：

- Edge 中正在播放的 Twitch 音频。

系统 WASAPI 回环可以捕获 Twitch，因此问题不在 Twitch 静音，也不是耳机设备没有输出，而是在 Chromium/Electron 的系统回环实现与 Edge 音频会话之间。可能原因包括：

- Edge 使用了 Chromium 回环未包含的音频会话；
- Bluetooth/OPPO 音频存在 offload 或路由差异；
- Edge 音频被放入独立或受保护的播放路径。

## 推荐替代方案

1. Edge 扩展 `tabCapture`：直接捕获 Twitch 标签页音频，再通过 WebSocket 传给 asmr3d。
2. Windows 原生进程级 WASAPI Loopback：按 `msedge.exe` 进程捕获，绕开 Chromium 系统回环限制。
3. 虚拟音频线：将 Edge 输出路由到虚拟设备，再由原生 WASAPI 捕获。

## 方案 2：原生进程级 WASAPI Loopback 验证

实现文件：

```text
tools/probe_process_audio.ps1
```

目标选择：

```text
通过 Windows 音频会话枚举找出正在播放的 msedge.exe 进程
```

实际捕获结果：

```text
目标进程：msedge
进程 PID：30880
采样率：48000 Hz
声道：2
位深：32-bit float
捕获时长：7.98 秒
峰值：-26.45 dBFS
RMS：-50.86 dBFS
有效浮点采样：751507 / 766080
```

捕获文件：

```text
dist/live-capture-validation/edge-process-loopback-8s.wav
```

该结果证明：

- 不依赖 Edge 的 tabCapture 扩展；
- 不依赖 Chromium desktopCapturer 系统回环；
- 可以通过目标进程 PID 捕获 Edge 的 Twitch 音频；
- 同样可以捕获 Chrome、Firefox 或其他浏览器，只要在运行时选择其活动音频进程。

## 最终结论

方案 2 可行，并且比 Electron 系统回环更适合当前产品。正式实现应采用：

```text
枚举活动音频会话
→ 让用户选择正在播放的浏览器或应用
→ Windows Process Loopback 捕获目标进程树
→ PCM 送入 Web Audio
→ asmr3d 空间渲染
→ 输出到耳机
```

Electron 自带的系统回环在当前机器上不能可靠捕获 Edge，但 Windows 原生进程级 Loopback 已实测成功。

## 集成到 asmr3d 后的功能范围

直播捕获输入进入 Web Audio 后，可以沿用现有渲染链：

| asmr3d 功能 | 直播模式下是否可用 | 说明 |
|---|---|---|
| 双耳兼容（推荐） | 可用 | 直接处理捕获的左右声道 |
| 浏览器 HRTF | 有限可用 | 需要把直播声音下混为单声道对象后再渲染 |
| 参数化 HRTF | 有限可用 | 同样需要单声道对象化 |
| Bypass | 可用 | 直接绕过空间处理 |
| 方位角、仰角、距离 | 可用 | 作用于直播声场或虚拟对象 |
| 输出音量、限幅 | 可用 | 可继续使用现有主输出链 |
| 播放进度、跳转 | 不可用 | 直播没有可回退的固定时间轴 |
| 完整文件离线导出 | 不可直接使用 | 需要先实时录音或持续写入磁盘 |
| 指定片段实时导出 | 可用 | 可实时记录处理后的 WAV |
| 多对象独立旋转 | 不可用 | 捕获的是混合声场，不是分轨对象 |

## CPU 实测

测试机器：

```text
20 个逻辑处理器
Windows 11 24H2
48 kHz / 2 channels
```

原生 Process Loopback 捕获参考实现：

```text
捕获时长：12.01 秒
捕获 CPU 时间：0.4688 秒
单核占用：3.90%
```

当前 Windows EXE 实时渲染：

```text
空闲基线：0.91% 单核
播放状态：52.73% 单核
播放相对空闲增量：51.82% 单核
折合 20 逻辑处理器总占用：约 2.59%
工作集内存：约 590 MB
```

预计集成后总占用：

```text
原生捕获 Helper：2%～5% 单核
进程间 PCM 传输：1%～3% 单核
现有 Web Audio 渲染：45%～60% 单核
总计：约 50%～68% 单核
```

在现代 20 线程处理器上，任务管理器总 CPU 约：

```text
2.5%～3.5%
```

在 4 核 8 线程处理器上，单核 60% 相当于系统总量约：

```text
7.5%～10%
```

该估算不包含：

- 多对象渲染；
- 大量卷积混响；
- 实时 WAV 写入；
- 离线完整导出；
- 低性能集成显卡或省电模式。

## 本地运行条件

Windows EXE 可以完全本地运行：

- 不需要联网；
- 不需要管理员权限；
- 不需要浏览器扩展；
- 不依赖特定直播平台；
- 原生 Helper 可以随 EXE 一起打包；
- 捕获目标从活动音频应用列表中选择。

需要注意：

- DRM 或受保护音频可能无法捕获；
- 目标应用退出或音频会话重建时需要重新选择；
- 捕获端点与耳机输出端点相同可能产生自反馈；
- 完整直播录制需要持续写入磁盘和额外内存。
