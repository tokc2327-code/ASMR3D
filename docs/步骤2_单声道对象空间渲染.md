# 步骤 2：基于步骤 1 素材的单声道对象空间渲染

## 版本说明

- 前置条件：步骤 1 音频素材库已经完成，位于 `materials/`。
- 本步骤只处理单声道声音对象。
- 普通双耳 ASMR 成品不属于本步骤的输入。
- 本步骤的目标是完成算法验证和实时渲染原型，不直接进入正式产品封装。
- 本步骤不实现头部追踪，所有方向均为相对听者坐标系的固定方位。
- 下表中的参数范围为本步骤的冻结约束，后续修改必须新建版本。

步骤 1 的交付物见：

```text
docs/步骤1_音频素材准备.md
materials/manifest.json
materials/SOURCES.md
```

可直接运行的渲染器见：

```text
renderer/index.html
renderer/server.mjs
docs/步骤2_渲染器实现方式.md
```

对于 KU100、假人头或普通立体声成品，可使用渲染器中的“双耳兼容”模式。该模式保留原始左右声道，只做整体横向声场、主观高度、距离和混响调整，不执行对象级真实旋转。

## 1. 冻结参数

| 控制参数 | 建议范围 | 作用对象 | 实现方式 |
|---|---:|---|---|
| 方位角 | −90°～+90° | 单声道对象 | HRTF 方位选择或插值 |
| 仰角 | −30°～+30° | 单声道对象 | 高度相关 HRTF 或耳廓滤波 |
| 距离 | 0.2～10 米 | 单声道对象 | 增益、近场、空气吸收、混响联动 |

### 1.1 参数含义

- 方位角是用户旋钮产生的相对增量，不是对双耳录音的声源反解结果。
- 仰角是用户旋钮产生的相对垂直偏移。
- 距离是渲染模型中的名义距离，不承诺与原始录音距离一致。
- 本步骤不接收头部姿态数据，不做世界方向锁定。

### 1.2 范围约束

```text
用户方位增量 ΔA ∈ [−90°, +90°]
用户仰角增量 ΔE ∈ [−30°, +30°]
渲染距离 r ∈ [0.2 m, 10 m]
```

方位角和仰角均相对听者坐标系计算。头部物理转动不会触发 DSP 参数变化。

## 2. 输入契约

每个单声道对象至少包含以下字段：

```json
{
  "object_id": "trigger_01",
  "audio": "trigger_01_mono.wav",
  "sample_rate": 48000,
  "base_azimuth_deg": 0,
  "base_elevation_deg": 0,
  "base_distance_m": 0.4,
  "gain_linear": 1.0,
  "near_field": true,
  "category": "asmr_trigger"
}
```

字段要求：

- `audio` 必须是单声道干声或已经明确对象化的单声道素材。
- `base_azimuth_deg` 必须位于 `[−180°, +180°)`。
- `base_elevation_deg` 必须位于 `[−90°, +90°]`。
- `base_distance_m` 必须位于 `[0.2, 10]`。
- `sample_rate` 在进入 HRTF 渲染前统一重采样到工作采样率。
- `category` 只影响渲染预设和测试分组，不改变硬件接口。

普通立体声或双耳录音只能作为对照素材，不能直接声明为单声道对象。

## 3. 坐标与角度计算

### 3.1 坐标系

采用右手坐标系：

```text
+X：听者右侧
+Y：听者前方
+Z：听者上方
```

方位角以正前方为 `0°`，向右侧为正，向左侧为负。

仰角以水平面为 `0°`，向上为正，向下为负。

### 3.2 用户控制后的位置

```text
θ_user = wrap180(θ_base + ΔA)
φ_user = clamp(φ_base + ΔE, −90°, +90°)
r_user  = clamp(exp_map(distance_knob), 0.2, 10.0)
```

其中：

- `wrap180` 将角度映射到 `[−180°, +180°)`。
- `distance_knob` 使用对数映射，不能直接线性映射厘米。

## 4. 渲染信号链

```text
单声道对象
    ↓
位置状态更新与参数平滑
    ↓
HRTF 查询与插值
    ↓
左右耳分块卷积
    ↓
近场处理
    ↓
距离增益、空气吸收、直达/混响比例
    ↓
可选房间反射
    ↓
多对象混合
    ↓
主限幅和耳机输出
```

所有对象必须使用同一个渲染时钟和同一套延时对齐规则。

## 5. HRTF 渲染

### 5.1 基本公式

```text
y_L[n] = x[n] * h_L(θ, φ, r)
y_R[n] = x[n] * h_R(θ, φ, r)
```

其中 `x[n]` 是单声道对象，`h_L` 和 `h_R` 是左右耳 HRIR。

### 5.2 数据库与查询

- 工作采样率统一为 48 kHz。
- 默认使用等间距方位和仰角网格。
- 数据库覆盖不足时，只允许最近邻或受控外推，不允许无提示地产生虚假方向。
- 方位查询至少覆盖用户的 `−90°～+90°` 控制范围。
- 若通用数据库只在有限仰角内测得，超出范围时应限制查询角度并记录警告。

### 5.3 插值

不能直接对未对齐的 HRIR 做简单线性插值，否则会破坏 ITD 并产生梳状滤波。

推荐顺序：

1. 提取并保存每条 HRIR 的传播延时。
2. 对最小相位部分或对齐后的响应插值。
3. 插值后再恢复传播延时。
4. 对插值结果做短时交叉淡化。

可接受的初始网格：

```text
方位角步长：5°～10°
仰角步长：5°～10°
```

UI 可以保留 `0.1°` 的内部精度，但不得把内部数值精度宣传成感知精度。

### 5.4 卷积

- 单对象原型可以使用直接卷积。
- 多对象或低延时模式应使用分块 FFT 卷积。
- 初始音频块建议为 128 或 256 帧。
- 48 kHz、256 帧对应约 5.33 ms 的块延时。
- 所有对象必须经过相同的卷积块对齐。

## 6. 仰角处理

用户仰角范围固定为：

```text
ΔE ∈ [−30°, +30°]
```

高度线索主要来自：

- 耳廓造成的方向相关陷波；
- 高频和低频的相对谱变化；
- 肩部及躯干反射；
- 左右耳频谱差异。

实现要求：

- 不能只用左右声道音量变化模拟上下。
- 通用 HRTF 的仰角线索存在明显个体差异。
- 若左右旋钮变化被测试者主要判断为音色变化，应判定为未通过。
- 不建议对相同信号同时叠加通用 HRTF 仰角处理和额外强 EQ。
- 第一轮只验证 `−30° / −18° / −8° / 0° / +8° / +18° / +30°` 七个位置。

## 7. 距离处理

### 7.1 距离范围

```text
r ∈ [0.2 m, 10 m]
```

距离旋钮采用对数或感知映射，不使用等距厘米映射。

### 7.2 距离增益

自由场中声压幅值随距离近似按 `1/r` 衰减。音频增益使用：

```text
G_direct = G_ref × (r_ref / r)
```

不能把能量衰减公式 `1/r²` 直接当作音频幅值增益，否则远距离会产生过度衰减。

从 0.2 米到 10 米的幅值差约为：

```text
20 × log10(0.2 / 10) ≈ −34 dB
```

该动态范围较大，必须保留增益平滑和主输出限幅。

### 7.3 近场

- `r < 1 m` 时启用近场模型。
- 近场需要改变头部阴影、耳间声级差、耳间延时和低频响应。
- 标准远场 HRTF 不能直接代表 0.2 米的近场结果。
- 缺少近场 HRTF 时，应把 0.2～1 米标记为近似模式。

### 7.4 空气吸收

- 空气吸收随频率和距离增加。
- 在 0.2～10 米范围内，空气吸收通常不是主要距离线索。
- 高频滚降必须温和，避免齿音消失和整体变闷。

### 7.5 直达声与混响

距离变化应联动：

- 直达声增益；
- 早期反射强度；
- 混响尾部增益；
- 直达声与混响比；
- 声场宽度；
- 低频近讲效应。

这些处理只能在明确对象化单声道素材上可靠执行。已经混入大量反射和后期处理的素材不满足本步骤输入契约。

## 8. 头部追踪范围

本步骤明确不实现头部追踪，也不保留头部姿态输入接口。

相关约束：

- 不接入头显、陀螺仪、摄像头或外部姿态追踪设备。
- 不根据听者转头重新计算 HRTF 方位。
- 不声明世界方向锁定或 360° 环绕稳定。
- 方位旋钮和仰角旋钮只控制相对听者坐标系的渲染位置。

如果后续版本加入头部追踪，应作为独立步骤重新定义输入、延时、平滑和验收标准。

## 9. 实时实现约束

### 9.1 工作参数

```text
采样率：48 kHz
音频块：128 或 256 帧
参数控制率：不低于 200 Hz
单线程音频回调预算：不超过 70%
```

### 9.2 参数平滑

- 方位角、仰角和距离分别平滑。
- 平滑时间建议从 20～50 ms 开始标定。
- HRTF 切换使用交叉淡化，不直接替换滤波器。
- 距离增益和混响比例同步平滑。
- 平滑必须在音频线程内无锁完成。

### 9.3 实时线程禁止项

- 禁止读取音频文件。
- 禁止网络操作。
- 禁止大块内存分配。
- 禁止等待锁。
- 禁止重建 HRTF 数据库。
- 禁止进行复杂 UI 绘制。

## 10. 多对象混合

第一轮验证限制为：

```text
1～4 个单声道对象
```

每个对象维护独立状态：

```text
object_id
θ_base
φ_base
r_base
ΔA
ΔE
distance_knob
current_hrtf_left
current_hrtf_right
current_gain
smoothing_state
```

混合要求：

- 每个对象独立执行 HRTF 和距离模型。
- 每个对象独立执行参数平滑。
- 混合后统一限幅。
- 多对象不能共享同一个滤波器切换瞬态。

## 11. 使用步骤 1 素材进行验证

步骤 1 已交付以下素材目录：

```text
materials/01_binaural_reference
materials/02_asmr_nearfield
materials/03_environment_distance
materials/04_test_signals
materials/05_mono_controls
```

### 11.1 使用方式

| 素材目录 | 在步骤 2 中的用途 |
|---|---|
| `01_binaural_reference` | 作为双耳渲染的外部化、方向和音色主观对照，不直接作为对象输入 |
| `02_asmr_nearfield` | 提取单声道内容后检查近场音色、动态和伪影，作为内容鲁棒性测试 |
| `03_environment_distance` | 作为距离和混响效果的主观参照 |
| `04_test_signals` | 作为参考信号或输出分析信号，不作为 HRTF 的方向真值 |
| `05_mono_controls` | 作为单声道内容输入和中心声像限制测试 |

现有素材主要是双耳或立体声预览，不能替代专门制作的单声道对象素材。步骤 2 必须另外准备单声道测试对象。

### 11.2 最小测试对象

至少准备以下单声道文件：

- 粉红噪声；
- 脉冲；
- 对数扫频；
- 干净人声；
- 耳语；
- 敲击；
- 摩擦；
- 纸张或包装袋声；
- 水声；
- 环境床。

每个测试对象建议制作 5～30 秒版本，原始格式优先使用 48 kHz、24-bit PCM WAV。

## 12. 验证矩阵

### 12.1 方位角

测试：

```text
−90° / −60° / −30° / 0° / +30° / +60° / +90°
```

检查：

- 方向是否连续；
- 左右耳级别差是否单调变化；
- ITD 是否随方向变化；
- 是否有瞬态爆音；
- 极左和极右是否保持音色稳定；

### 12.2 仰角

测试：

```text
−30° / −18° / −8° / 0° / +8° / +18° / +30°
```

检查：

- 是否能区分上下；
- 是否只表现为音量或亮度变化；
- 不同耳机的差异；
- 不同头型和耳型测试者的差异；
- 前后混淆是否明显增加。

### 12.3 距离

测试：

```text
0.2 / 0.4 / 0.7 / 1.2 / 2 / 4 / 7 / 10 米
```

检查：

- 响度归一化后是否仍有距离变化；
- 高频是否过闷；
- 低频近场是否过重；
- 混响是否吞掉直达声；
- 大距离变化是否导致削波；
- 近场 HRTF 缺失是否造成明显错误。

## 14. 主观测试

首轮建议使用：

```text
12～20 名听者
有线耳机
统一响度
随机顺序
盲听
```

分别测试：

1. 左中右方向识别。
2. 上中下方向识别。
3. 远近距离识别。
4. 音色变化是否可接受。
5. 外部化感。
6. 快速旋转是否平滑。

偏好测试与定位测试必须分开统计。用户喜欢旋钮效果，不等于系统能够准确定位。

## 15. 步骤 2 的完成标准

达到以下条件才进入步骤 3：

1. 单声道对象可以在 `−90°～+90°` 方位内连续渲染。
2. 用户仰角 `−30°～+30°` 可以被多数目标用户感知。
3. 仰角变化不能只依赖左右音量差或整体亮度差。
4. 距离在 `0.2～10 米` 内可调，并且响度归一化后仍有距离感。
5. 参数连续变化没有爆音、削波或明显梳状滤波。
6. 128 或 256 帧块大小下，音频回调不超过预算的 70%。
7. 端到端延时稳定，不随参数变化。
8. 1～4 个对象的 CPU 和内存没有持续增长。
9. 所有测试结果和失败案例均已记录。

## 16. 不在本步骤范围内

- 从普通双耳 ASMR 中分离单个声源；
- 从立体声录音恢复真实世界坐标；
- 个性化耳廓扫描；
- 完整房间几何重建；
- 头部追踪和头部姿态输入；
- 与 VR 场景的视觉同步；
- 面向消费者的最终 UI；
- 对接触声、骨传导和皮肤传导的完整物理建模。

步骤 2 的交付物应当是算法原型、测试数据、客观测量和盲听报告，而不是正式产品。
