# 步骤 2 渲染器实现方式

## 1. 本版实现目标

本版目标不是提供最终产品级 HRTF 引擎，而是提供一个可直接运行、可听、可切换和可观察的步骤 2 验证器。

本版输入：

```text
单声道对象
```

本版输出：

```text
耳机左右声道双耳信号
```

本版参数：

```text
方位角：−90°～+90°
仰角：−30°～+30°
距离：0.2～10 m
头部追踪：不做
```

## 2. 输入实现方式

| 方式 | 本版状态 | 说明 |
|---|---|---|
| 单声道 WAV/FLAC/OGG 文件 | 支持 | 作为标准对象输入 |
| 步骤 1 素材库选择 | 支持 | 从 `materials/manifest.json` 读取 |
| 本地文件上传 | 支持 | 由浏览器读取并送入音频图 |
| 立体声或双耳输入下混为 mono | 支持 | 仅用于原型对照，不代表真实对象分离 |
| 创作者提供分轨和方向元数据 | 后续 | 正式对象模式应使用该方式 |
| 从双耳录音反解对象 | 不采用 | 信息不足，不作为步骤 2 前提 |

## 3. 空间渲染实现方式

### 3.1 浏览器内建 HRTF

本版默认方式。

实现：

```text
AudioBufferSource / MediaElementSource
→ PannerNode
→ panningModel = "HRTF"
→ 左右耳输出
```

优点：

- 无需外部 HRTF 数据库；
- 浏览器原生支持；
- 能快速获得可听的方向变化；
- 支持实时位置更新。

限制：

- HRIR 由浏览器实现决定，不可控；
- 不能指定特定头型或耳型；
- 距离模型主要由浏览器决定；
- 不适合作为最终产品算法验收。

### 3.2 参数化 HRTF 近似

本版作为可观察和可调的第二路径。

包含：

```text
声道增益
→ 耳间时间差
→ 头部阴影低通
→ 仰角峰值滤波
→ 空气吸收低通
→ 近场低频提升
```

优点：

- 每个线索可单独检查；
- 便于调试和教学；
- CPU 开销低；
- 不受浏览器 HRTF 黑盒影响。

限制：

- 不是实测 HRIR；
- 耳廓线索是近似值；
- 对不同听者和耳机的一致性有限；
- 不能替代最终个性化 HRTF。

### 3.3 SOFA/HRIR 直接卷积

后续生产级方式。

```text
单声道对象
→ 按方向查询 HRIR
→ h_L、h_R
→ y_L = x * h_L
→ y_R = x * h_R
```

适用范围：

- 固定 HRTF 数据库；
- 少量对象；
- 非实时或高延时原型。

### 3.4 分块 FFT HRTF 卷积

后续低延时、多对象方式。

```text
分块输入
→ FFT
→ 与左右耳 HRIR 频域相乘
→ IFFT
→ overlap-add 或 overlap-save
```

这是正式实时引擎的常用方案。

### 3.5 最小相位 HRTF 与 ITD 分离

后续高音质方式。

```text
HRIR
→ 提取传播延时
→ 分解最小相位幅频响应
→ 插值幅频和延时
→ 重建左右耳滤波
```

该方式可减少直接插值 HRIR 导致的梳状滤波。

### 3.6 球谐 HRTF 插值

研究级方式。

```text
HRTF 数据库
→ 球谐展开
→ 任意方向重建
→ 左右耳卷积
```

适合连续移动和头部追踪，但需要更复杂的数据库和计算。

### 3.7 Ambisonics 渲染

后续替代方式。

```text
单声道对象
→ Ambisonic 编码
→ 声场旋转
→ 双耳解码
→ 耳机输出
```

优势是整体声场旋转简单，适合多对象场景。

### 3.8 纯振幅声像

仅作为对照。

```text
L = cos(角度) × mono
R = sin(角度) × mono
```

缺点是不能产生正确的 ITD、前后和高度线索。

### 3.9 双耳兼容模式

本版已实现，专门处理 KU100、假人头和普通立体声 ASMR 成品。

```text
原始 L/R
→ StereoPanner 整体横向移动
→ 高度相关频谱滤波
→ 空气吸收
→ 近场低频
→ 距离增益
→ 可选合成混响
→ 左右耳输出
```

关键要求：

- 整个过程保留下混前的原始左右声道，不再压成 mono。
- 横向控制只移动整个声场，不改变录音中每个声源的原方向。
- 高度控制是主观频谱修饰，不是对原始耳廓线索的真实反演。
- 距离控制只能模拟远近，不能恢复原始直达声与混响比。
- 该模式应明确标记为“双耳兼容”，不能宣传为真实三维旋转。

## 4. 距离实现方式

| 方式 | 本版状态 | 说明 |
|---|---|---|
| 距离反比增益 | 支持 | 声压按 `refDistance / distance` 衰减 |
| 对数距离旋钮 | 支持 | 避免近距离变化过慢、远距离变化过快 |
| 空气吸收低通 | 支持 | 距离越远，高频截止越低 |
| 近场低频提升 | 支持 | 1 m 内逐步增加低频 |
| 直达声与混响比 | 支持 | 距离越远，合成混响湿声比例越高 |
| 近场 HRTF | 后续 | 需要专用近场数据库 |
| 多普勒 | 不采用 | 本版距离是静态控制，不模拟运动速度 |
| 完整房间声学 | 后续 | 需要房间几何和材质 |

## 5. 头部追踪实现方式

本步骤明确不做头部追踪。

以下方式均不在本版实现：

- VR 头显姿态；
- 手机陀螺仪；
- AirPods 姿态；
- 摄像头头部姿态估计；
- 惯性传感器融合；
- 世界方向锁定；
- 视觉与听觉同步。

后续如果加入头部追踪，应作为独立步骤重新定义坐标、延时、预测和验收标准。

## 7. 本版实际音频链

```text
素材或本地文件
→ 对象路径显式单声道下混
→ HRTF / 参数化 / 双耳兼容 / Bypass
→ 距离处理
→ 合成混响
→ 主增益
→ 压缩限幅
→ 耳机输出
```

### 7.1 WAV 导出链路

本版支持两种导出方式。

完整文件使用离线渲染：

```text
读取并解码完整源文件
→ OfflineAudioContext
→ 当前模式与空间参数
→ 主限幅输出
→ 16-bit 或 24-bit PCM 编码
→ WAV 下载
```

指定片段使用实时输出捕获：

```text
当前模式与空间参数
→ 主限幅输出
→ ScriptProcessor 双声道 PCM 捕获
→ 16-bit 或 24-bit PCM 编码
→ WAV 下载
```

导出特点：

- 捕获的是用户当前实际听到的渲染结果。
- 支持浏览器 HRTF、参数化 HRTF、双耳兼容和 Bypass。
- 完整文件不受实时播放速度限制，可在后台执行。
- 指定片段支持当前播放进度或文件开头作为起点。
- 指定片段支持 5、15、30、60、120 秒。
- 导出期间冻结模式、空间参数和素材选择，防止成品中途改变。

限制：

- 完整文件需要同时保存解码音频、离线渲染结果和 WAV 编码结果，长文件会产生较高内存峰值。
- 完整文件渲染速度取决于文件长度、HRTF、混响和 CPU。
- 指定片段实时捕获时，页面切到后台或系统音频回调不稳定可能产生缺帧。
- 浏览器预览保持在 48 kHz；完整离线导出使用源文件采样率。

## 8. 可测试项

- 方位角连续变化；
- 仰角连续变化；
- 对数距离变化；
- HRTF 与参数化路径差异；
- Bypass 与空间化差异；
- 单声道素材和双耳下混素材差异；
- 参数切换是否有爆音；
- 当前渲染参数能否完整导出为 WAV；
- 限幅是否削波；
- 不同耳机下的方向感和音色差异。

## 9. 已知限制

- 浏览器 HRTF 是黑盒。
- 参数化 HRTF 没有使用真实 SOFA 数据。
- 对象路径的立体声下混会丢失原始空间线索。
- 双耳兼容模式不做真实声源旋转，只调整整体听感。
- 混响是合成脉冲，不是真实房间。
- 距离为感知映射，不是物理测量。
- OGG 预览是有损格式。
- 本版没有头部追踪。
